# v0.13.0

Drafted 2026-09-13.

A release about **builds that lied quietly**. The two framework fixes at its
centre share a shape: a defect that produced no error, no warning and a
plausible-looking result, so nothing downstream could tell it had happened.
A build subprocess that imported the wrong checkout served an **empty table**
and raised nothing; `panel_ids` raised a `TypeError` under pandas 3.0 that
surfaced only as an opaque `CalledProcessError` from a wave `make`, and only on
a forced rebuild. Around those: two new framework screens (Site I and Site Q's
extension), and country fixes in Malawi, Tanzania, Nigeria, Panama and
GhanaLSS.

## Upgrading: every cache re-warms

**Both parquet tiers invalidate, for every table in every country.** The #803
fix edits `Wave.grab_data`, which carries `@build_transform()`, so
`build_transforms_fingerprint` moves for every table -- measured, all five
probed values (`food_acquired`, `crop_production`, `household_roster`,
`cluster_features`, `sample`) -- and that fingerprint is folded into the
L2-country hash *and* into `Wave._input_hash`. The first read of each table
rebuilds from source. On the corpus this release was tested against that is
**377 L2-country parquets / ~22 GB**.

As in 0.12.0, **#866 is still open**: a country-level script-path table whose
Makefile has no rule for its `var/` target will not rebuild on the hash move
(`LSMS_NO_CACHE=1` does not escape it) -- run `lsms-library cache clear
--country {C}` first.

One consequence worth stating, because it bit during release testing: a
**stale cached parquet can fail a test that a re-warm fixes**.
`tests/test_table_structure.py` reads cached parquets directly rather than
through the API, so `GhanaLSS/interview_date` reported a missing `visit` index
level until the re-warm rewrote it. If you see a structural test fail on a
table you have not touched, check the parquet's age before the code.

## Behaviour changes you will see in returned data

- **A build subprocess now imports the library that spawned it (#803).** Both
  places the build path shells out constructed their child's environment, and
  neither was correct: `Wave.grab_data`'s wave-level fallback set no
  `PYTHONPATH` at all, and `Country.run_make_target`'s `build_env` set it to
  `countries_root()` -- a directory that is **not importable as
  `lsms_library`**, so a child given it imports exactly what it would have
  imported with no `PYTHONPATH` set. It read as a guard and was not one.
  A child importing a different checkout fails `_resolve_data_path`'s
  under-`countries_root()` test, writes its parquet **in-tree**, and the
  library then ignores in-tree parquets by design -- so the table came back
  **empty, with no error raised**. Measured end-to-end on one Uganda wave
  forced to rebuild: `(0, 0)` and one in-tree parquet before, `(40749, 3)` and
  none after. Both sites now share `country._script_subprocess_env`, so they
  cannot drift apart again.

- **`panel_ids` no longer raises under pandas 3.0.** `df.loc[:, col] = ...`
  sets *in place* and preserves dtype, so writing `format_id`'s strings into a
  float64 id column is a lossy setitem: pandas 2.x upcast with a warning,
  pandas 3.0 raises. Any country whose ids arrive numeric lost every table that
  depends on `panel_ids.json` -- for Uganda, all of them. The regenerated
  `panel_ids.json` / `updated_ids.json` are **byte-identical** to the committed
  versions, so this restores prior output rather than changing it.

- **Site I reports a NaN on a declared index level (#847).** A row whose
  declared index level is NaN was deleted outright by the collapse
  (`groupby(dropna=True)`) and nothing said so. It is now reported.

- **Site Q extends to `food_acquired.Quantity` (#884).** The implausible-value
  screen, previously `crop_production.Quantity` only, now also screens acquired
  food. Warn-only: it counts and names, and never clips, drops or NaNs.

- **`plot_features.Area` is served in hectares for six countries (#879)**,
  which previously served the native unit while `data_info.yml` declared
  hectares and `AreaUnit` sat unread by any framework code. Site Q now screens
  `plot_features.Area`, which is what catches a recurrence.

- **Malawi recovers Cassava, 'other' and tree crops (#869)** in 2016-17 and
  2019-20, previously dropped silently by a crop-code mismatch.

- **Tanzania stops flooring food quantities (#835)** in
  `new_harmonize_units`, where an `astype(int64)` truncated fractional
  quantities.

- **Nigeria reads the C8 SIZE field in `community_prices` (#834)**, so `g`
  and `cl` rows carry their container size.

- **Panama stops fabricating `Expenditure = 0` (#825)** on non-purchased food
  rows, where zero meant "not purchased", not "free".

- **Metric spellings seeded, and stated-vs-inferred kg reported (#838)**,
  where `_get_kg_factors` contradicted the survey's own unit labels.

## Framework and docs

- `ll.recall` / `ll.derivations` submodule shadowing is documented and pinned
  (#883).
- GhanaLSS 2016-17 community-price quantities are qualified: `QTY` holds the
  container **content**, not the count (#826).
- The `#842` kg-factor agreement test now asserts **per unit** rather than on
  pooled rows. #850's plural-metric fix (`kgs`, `lts`) widened the compared
  population 1,922 -> 5,410 by resolving six container units, and containers
  are where a household's own reported weight legitimately varies -- so the
  pooled within-+/-20% share fell to 74.7% while the pooled median stayed
  1.000. 9 of 10 units measure a median ratio of exactly 1.000.
- `tests/test_build_subprocess_env.py` and `tests/test_panel_ids_dtype.py` pin
  the two framework fixes; both were mutation-proved against the pre-fix tree.
