# v0.12.0

Drafted 2026-09-12.

A release about what a served number *is*. Two changes carry it. First, a value
the library **computes** from survey answers, rather than reads off them, now
says so on the row: `lsms_library/derivations.py` adds a registry, a
`Derivation` column, an `attrs['derivations']` summary and
`Country.derivation_inputs()`, and the first two instances correct numbers that
had been served as answers for years -- GhanaLSS's 1980s own production, and
purchased food expenditure in twelve EHCVM waves. Second, the three core index
collapses no longer return a per-column composite: they select the group's
**most complete observed row**, which reverses the 2026-07-13 "complementary
missingness is completion" doctrine and settles #871. Around those: Ethiopia's
food sources read from their own questions, four wave-level data fixes, and the
items held back from 0.11.2 (the food kg item axis, Malawi's shipped factors,
`Feature('crop_production')` on its declared index, and `plot_id`).

## Upgrading: every cache re-warms

**Both parquet tiers invalidate, for every table in every country.** #871's
Site 1 lives in `Country._normalize_dataframe_index` and is tagged
`@build_transform(tables=())`, so `build_transforms_fingerprint` moves for
every table, and that fingerprint is folded into the L2-country hash *and* into
`Wave._input_hash` (the `btf=` part). The first read of each table rebuilds
from source. `Wave.cluster_features` (Site 2) additionally gains
`@build_transform(tables=['cluster_features'])`, because it had reached no
table's fingerprint at all: before this, a Site-2-only edit would have served
stale composites indefinitely.

Two practical notes. **#866 is still open**, so a country-level script-path
table whose Makefile has no rule for its `var/` target will not rebuild on the
hash move (20 tables in 13 countries; `LSMS_NO_CACHE=1` does not escape it) --
run `lsms-library cache clear --country {C}` first. And much of the corpus would
have re-warmed anyway: `plot_id` moved 274 of 337 probed hashes across 12
countries, #876 moved `mapping.py` and `data_info.yml` in 12 EHCVM waves, and
Ethiopia, Uganda, Niger, Malawi and GhanaLSS each moved a country module or a
`data_scheme.yml`. #871 subsumes all of it.

## Behaviour changes you will see in returned data

- **Core serves an observed row, not a composite (#871).** `groupby().first()`
  is not "the first row": it returns the first non-null value of each column
  independently, so a group whose rows disagreed was served a record existing
  nowhere in the survey -- core reported the group as destroyed and then served
  the completion. All three sites (`_normalize_dataframe_index`,
  `_collapse_to_cluster_grain`, `feature._collapse_duplicate_index`) now call
  one helper, `country.most_complete_row`, which counts non-NA cells over the
  columns core does not reduce and breaks ties by original order. Measured on
  the warm corpus (112 collapsing cells, 30,815 disagreeing index tuples,
  105,137 audited destroyed rows): **544 rows change (Site 1 543, Site 2 1) and
  `served_na_new` is 0** -- no cell comes back absent where `first()` found a
  value in the same group. The plan's simpler `nth(0)` would have changed 1,025
  rows and emptied 2,714 cells. Niger `household_roster` 2014-15 now serves the
  head's line rather than the blank line sharing its broken `pid`; Nigeria
  `cluster_features` 2013Q1 keeps the GPS fix four of five households report.
  The residual is Kosovo `housing` 2000 (524 rows, `Type` and `Electricity`),
  18 rows of Niger and Burkina Faso `plot_inputs`, and one Malawi cluster on
  `Rural`: equally complete rows, different values. The **audit did not move**
  -- it reports loss, which is reducer-independent -- and a row with a NaN in a
  declared index level is still deleted by `groupby`'s `dropna` (#323 §3b).
  Completion keeps its home in `build_transforms.reduce_to_agreed`, invoked in
  writing by a country author. `Derivation` is excluded from the completeness
  score on both branches: a library-computed flag must not decide which survey
  row is served.
- **GhanaLSS 1987-88 and 1988-89 own production is a derived fortnight.**
  `Y12B.VFOODCPD` answers "how much would it cost to buy the amount they ate
  each time" -- one eating occasion -- and had been served as the fortnight's
  own-production expenditure beside 12A's genuine fortnight recall, with
  nothing in the frame telling them apart. The 44,112 produced rows now carry
  `GhanaLSS::food_acquired::12b-fortnight` = `VFOODCPD x TFOODC x
  (14 / days-per-UTFOODC) x MFOODCLY / 12`, the year-average fortnight, which
  is GSS's own `HPFOOD / 26`: median ratio **1.018** against `EXPEND.HPFOOD`.
  Pinned totals move to 1,513,769 (`unitvalue`) and 1,693,174 (`units`); three
  1987-88 rows with `MFOODCLY == 0` derive to 0.
- **EHCVM purchased `Expenditure` is a derivation, not the last purchase
  (#876).** Eight countries, twelve waves: the served `Expenditure` was
  `s07bq08`, the value of one last purchase within 30 days, sitting beside a
  7-day consumption quantity. It is now `(s07bq03a - s07bq04 - s07bq05)` times
  the last-purchase unit value -- construction C, the survey's own identity,
  chosen by @ligon because it reproduces the World Bank's `ehcvm_conso`
  `depan(Achat)` within 1% on **99.5 to 100%** of the rows where the candidates
  differ (gross 0%, net-of-production 13 to 49%). Purchased `Expenditure` moves
  **-1.7% to -37% by wave**, and 9.7 to 25.6% of purchased rows are NA (no last
  purchase reported, or a unit that cannot be matched to the consumption unit),
  disclosed per wave. Gifts (`s07bq05`) are served as `s='inkind'` rows
  carrying `Quantity` only; the World Bank's `depan(Don)` valuation is an
  imputation and is not served. One shared function (`lsms_library/ehcvm.py`),
  eight per-country registry entries, raw inputs joinable in all twelve cells.
- **Ethiopia serves each food source from its own question (#874).**
  `purchased` is Q3, `produced` Q5, `inkind` Q6, each in its own unit; the
  `clip(Q2 - Q3, 0)` residual is gone. That residual booked gifts as own
  production and, through `min(Q2, Q3)`, truncated purchases. Q5 agrees with it
  exactly wherever both are positive, and `Q2 = Q3 + Q5 + Q6` closes on 97.6 to
  100% of rows per wave. Impossible answers are counted and named, never
  clipped (`Q3 > Q2` in 131/235/1/0/56 rows by wave, `Q5 > Q2` in 17/53/0/4/14).
  The per-source read **un-suppresses 2011-12's 1000x unit slips**:
  `food_quantities(units='kgs')` goes 7.47e5 to **1.73e6 kg**, which is **not
  signed off as a correction** -- #884 is filed to extend the Site Q screen to
  `food_acquired.Quantity`. Separately, `transformations.food_kg_factors` now
  applies the `_unit_sentinel_mask` its docstring already claimed: Ethiopia's 22
  unit-less rows had been delivering 9.88M of 12.47M kg. Every other measurable
  country moves 0.0%.
- **Uganda `intercropped` reads the crop-stand question, in both seasons
  (#872).** It was wired to the seed-use question, so a served `True` meant
  "did not use seed". All seven waves now read `a4aq7/a4bq7`, `a4aq8/a4bq8` or
  `s4aq08/s4bq08`, and season B reads its own roster rather than season A's:
  12,855 of 46,418 comparable rows corrected, 14,671 newly populated, 255 newly
  NA, and 2009-10 and 2010-11 go from 100% NaN to populated. The old flag agreed
  with the right one on 53% of rows.
- **Niger 2011-12 labour hours divide by 12, not 52 (#877).** `ms04q31` is days
  per *week*, in both the French and English variable labels and in the
  questionnaire, so `days x hours` is already usual weekly hours and the old
  `(months x days x hours) / 52` treated days as days per month. Sum of hours
  goes 79,692 to **328,477** (mean per worker 7.02 to 28.94, max 1,710 to 238),
  and the 2014-15 / 2011-12 per-worker ratio 3.12 to 0.76. The survey's declared
  `manquant` codes are NA'd before the multiply in both waves (2014-15 moves by
  one row, 221,526 to 221,517). This is a deliberate departure from World Bank
  parity, disclosed in the script docstring, `data_scheme.yml`, `niger.py` and
  `CONTENTS.org`. The 2011-12 participation dummies are 30-day and 12-month
  questions under a last-7-days name: disclosed, not changed, split out as #882.
- **GhanaLSS food purchases and own production, three wave-level fixes.**
  1991-92 read `s9bq2..s9bq10`, skipping the first and largest stem -- 58,132
  positive values, C12,428,840, **16.22%** of the C76,609,939 in the module,
  missing from every GLSS3 number this library has served. 2005-06 dropped
  `s8hq3`, the 2nd-visit own-production quantity, on the strength of a
  misleading Stata label: 21,252 rows and 4,777 households added at
  `(produced, visit 2)`, every other row byte-identical. And `visit` is now the
  **calendar** visit rather than the source question number in all five
  multi-visit waves -- 8H opens with two screeners and 9B does not, so a
  purchase and the own production consumed at the same visit sat two apart, and
  `visit` was not sliceable across `s`. GLSS3 is stratified and no other wave
  is, so summing `visit` away gives 30 days for an urban household and 14 for a
  rural one: recorded, not fixed.
- **Burkina Faso 2014 food rows were deleted, not summed (#851 Phase I).** Only
  passage 1 of the four EMC passages fields the quantity grid, so `u` -- a
  declared index level -- arrived NaN for passages 2 to 4 and
  `groupby(dropna=True)` deleted those rows before the additive sum could fire.
  Fixed at the country level with the `Unknown` `u` sentinel and a `visit`
  level: delivered 2014 rows 97,361 to **557,692**, Expenditure 80,286,096 to
  **342,110,515 CFA**, rows deleted on a NaN key 460,438 to 0. 2018-19 and
  2021-22 unchanged to the last digit. This is the cell the grain-collapse
  section names as the corpus's worst NaN-key loss.
- **GhanaLSS `visit` is one integer type.** The mixed-type level made 11.56% of
  `food_acquired` rows silently unjoinable, and which way it failed depended on
  how the caller spelled the key. The mixed level was the *cold* build: warm,
  pyarrow coerced the level to string on the parquet write, so the same call
  returned differently typed data depending only on cache warmth. Conserved bit
  for bit -- 5,317,365 rows, identical index, zero change in the sums of
  `Quantity`, `Expenditure` and `Price`.
- **The food-side kilogram inference has an item axis, a real denominator and a
  dispersion gate (#850, closed 2026-09-10).** Step 2 medianed `Expenditure`
  rather than `Expenditure / Quantity`, so the factor was kilograms per
  transaction row: asked what a kilogram weighs, the old chain answered 0.87 to
  2.0 by country and now answers 1.0 by construction. No step carried `j`, so
  one factor per unit label served a whole country -- Malawi's `Piece` is shared
  by 133 items whose separately estimable weights run from 1 g to 1.8 kg. Totals
  in `food_quantities(units='kgs')` move Malawi -70.6%, Ethiopia -81.9%, Niger
  -49.6%, EthiopiaRHS -32.3%, Uganda -14.8%, Mali -19.5%, Nigeria -6.8%,
  Tanzania -2.6%, GhanaLSS +18.6%. **Three of those cells are superseded inside
  this release**, because the input rows changed and not the inference: Ethiopia
  1.73e6 kg (-58.0% on the same baseline) after #874, Mali 1.31e7 and Niger
  2.99e5 after #876. Per-row provenance rides on the frame (`KgFactorSource`,
  `attrs['kg_factor_sources']`); read the `unit` count before trusting a per-kg
  number, since that is the old u-pooled factor.
  `FOOD_KG_BASELINE_MAX_SPREAD = 10` refuses a `(t, j)` baseline whose own
  reports disagree by more than tenfold -- which is what removes Niger's 0.33 kg
  tiya -- and a refused row is tagged, never dropped.
- **Malawi's shipped crop conversion tables are wired, and `condition` is a real
  level (#854, closed 2026-09-10).** `malawi.crop_conversion_factors()` returns
  the shipped-factor frame keyed `(crop, u, condition, region)`. `crop_code` is
  a variety label finer than our `crop`, so `_collapse_varieties` keeps a key
  only where every variety agrees (23 of 314 seasonal and 8 of 92 tree keys
  disagree, dropped and counted, never averaged); unmatched unit labels are
  dropped rather than folded onto a coarser one; `region` needed translating
  ('South' against `cluster_features`' 'Southern').
- **Malawi's "grams" factor was wrong by 10x, and dead (#878).** It used 0.01
  where the conversion is 0.001, and fired only on an exact 0.0 factor, which
  neither conversion table contains. Served output is proven byte-identical on
  all five waves; the dead fallback is removed at four IHS3+ sites and 2004-05's
  live kilogram arm kept.
- **`plot_id` is the plot axis everywhere.** `plot_features` already said so in
  all 23 countries; the canonical index of `crop_production` now does too, and
  every plot-grain transform (`harvest_kg`, `nitrogen_kg`, `seed_kg`,
  `yield_kg`, `fertilizer_rate`) emits `plot_id`. Both spellings stay accepted,
  and 11 countries' declared levels were renamed one at a time -- Nigeria's
  `sold_on='plot'` join-grain flag and the mapping dicts whose values are source
  column names were deliberately left alone. A shared axis name is not a shared
  vocabulary: Uganda keys `crop_production` plots `{hhid}-{parcel}-{plot}` and
  `plot_features` plots `{parcel}_{suffix}`.
- **Ethiopia `shocks` has one builder (#875).** The YAML path and the
  still-wired wave and country scripts disagreed on the sign of `Increase` and
  on whether `j` was an index level, and `make` could not build W5 but left wave
  parquets the fallback would serve. The scripts and Makefile rules are gone,
  and `AffectedFoodStock` and `Occurrence` are carried onto the YAML path.
  `Occurrence` is required, not optional, because `optional:` is country-grain
  and the absence is wave-grain: W4 and W5 never ask it, and Site B reports
  those two waves, as it should. Served `Affected*` counts unchanged per wave,
  plus three rows whose only answers were in the two new columns.

## Framework and API

- **The derived-values mechanism.** A registry in
  `countries/{C}/_/derivations.yml` (a sibling of `population.yml`, never a
  block in `data_scheme.yml`) plus framework-level
  `lsms_library/derivations.yml`, keyed `country::table::name` with the wave
  scope in the entry rather than the key. A `Derivation` column, declared
  `optional` in the canonical `data_info.yml`, carries the key on exactly the
  rows the function produced; `attrs['derivations']` summarises what is below;
  `Country.derivation_inputs(key)` returns the raw inputs under their original
  survey names, re-keyed through `updated_ids` so they join to the served rows;
  `ll.derivations()` tabulates the registry. The loader refuses an entry missing
  `rule`, `function`, `inputs`, `raw_variables` or `assumptions`, or an
  assumption without a `basis`. Two decisions worth knowing: a derivation
  function takes **no options**, since a cached parquet must be one identifiable
  construction (re-derive from `derivation_inputs` if you want another), and
  there is deliberately no warning at `Feature()` level, because the `attrs`
  summary already says what is below. The mechanism moved 0 of 14 probed cache
  hashes; what costs is where the function lives, a country module being in
  every table of that country's hash. The 2026-09-11 census found about **410**
  construction sites in the corpus, roughly a fifth disclosed nowhere a user
  looks; nine are registered today. Guide: `docs/guide/derivations.md`; design
  and census: `SkunkWorks/derived_values.org`.
- **`Feature()` re-attaches every `attrs` carrier (#873).** `attrs` survive an
  operation only when every input agrees, so the cross-country concat drops them
  by design; `feature._ATTRS_CARRIERS` captures population, recall and
  derivations per country and re-attaches each through its own module's
  `merge_attrs`, for the kept countries only. Measured:
  `Feature('food_acquired')(['GhanaLSS', 'Guatemala'])` carried no recall record
  and now carries both, and no derivations summary and now carries GhanaLSS's.
  Read-path, so 0 of 211 cache hashes moved. Found on the way:
  `lsms_library/__init__.py` rebinds the submodule names `recall` and
  `derivations` over public callables, so `from . import recall` inside the
  package yields a function -- `feature.py` imports by symbol, and the shadowing
  is #883.
- **`RecallRecord` is an immutable `dict` subclass**, so an API frame carrying
  `attrs['recall']` can be written with `to_parquet()`: pandas serialises
  `attrs` with a bare `json.dumps`, and the frozen dataclass made that raise for
  17 countries. Same solution as `PopulationRecord`, deviations stated in the
  class docstring.
- **Recall records (#851 Phase I).** `ll.recall()` and `attrs['recall']` report
  what a food number's reference period is, from 20 packaged
  `countries/{C}/_/recall.yml` files. Four facts, separate on purpose:
  `recall_days` is the length of one ask; `n_asks` counts asks rather than
  visits (GLSS7 fields seven visits and asks food at six, so exposure is 30
  days, not 35); `within_wave_variation` names the axis for the five cells whose
  delivered window differs inside the wave; `basis` is the evidence ladder,
  since only 8 of 34 stated windows are questionnaire-grade. There is
  deliberately no `period=` and no annualisation -- reported spend barely
  responds to the realised interval (elasticity 0.018 on GLSS4), so dividing by
  days injects fieldwork tempo. No cache hash moves; #851 stays open for Phase
  II.
- **`Feature('crop_production')` assembles on the declared canonical index**
  (#775, closed 2026-09-10; refs #569). With no `index_info` entry it fell
  through to the modal index-shape filter, which excluded the country that had
  moved *toward* the canonical index -- adding `condition` to Malawi dropped
  131,379 rows, 81% of the red-team's four-country call -- and made survivors
  depend on argument order, three orderings of the same four countries returning
  three different single countries. `index_info`, `level_aliases` and
  `missing_level_sentinels` now declare it, and a canonical level a country
  lacks is filled with a real sentinel rather than `pd.NA`.

## Documentation and maintainers

- `docs/guide/derivations.md` and a `CLAUDE.md` section for the mechanism;
  `SkunkWorks/derived_values.org` for the design and the corpus census.
- `slurm_logs/gh871_grain_census/`: `bench/grain_census_871.py` takes
  `--reducer {nth0,most-complete}`, so both rules are measurable from one script
  and one warm cache, and census-destroyed reconciles with stamped-destroyed on
  51 of 51 cells.
- A visit-date audit of all seven GLSS rounds: five of seven ship per-visit
  dates, only 2016-17 (CAPI) ships the intake date alone, and no GLSS instrument
  records a clock time.
- **Run the test suite the way the Makefile does**: `-n $(nproc)
  --dist=loadfile` *plus* `LSMS_BUILD_WORKERS=1` (CLAUDE.md, scrum-master
  addendum 3b). Bare `pytest -n 40` scatters one file's tests across workers, so
  several build the same table at once; on 2026-09-11 that left three xdist
  workers blocked behind `_parallel_waves` children that had inherited DVC's
  sqlite handle across `fork`. The Makefile recipe: 5,666 passed in 566 s, no
  worker lost. Write pytest output to a file, never through a pipe.
- A Python groupby callable makes pandas deepcopy `df.attrs` once per group, so
  adding `Derivation` as a third such column pushed GhanaLSS `food_acquired`
  past a 1,200 s test timeout. Both overlays are vectorised now, and verified
  equivalent rather than assumed: 0.12 s against 51.8 s for the additive sum and
  0.25 s against 12.4 s for the `Derivation` union, on a 400k-row / 200k-group
  frame, byte-identical output.
