* Status / mandate
Design for implementation.  *Nothing implemented.*  Builds on
[[file:data_access_restrictions.org][data_access_restrictions.org]] (2026-09-04), which is EL's shape and
whose decisions this note inherits by id.  What is new here is (i) a measured
fact the 09-04 note was built on and which turns out to be false -- the World
Bank API-key gate it says discharges self-service data does not fire on any
read path; (ii) one step of the 09-04 design that EL reversed on 2026-09-17;
and (iii) an encryption mechanism EL named on 2026-09-17 that changes the
answer to the 09-04 note's one open question.

** Inherited from 09-04, unchanged
- D1 :: A push is never blocked.  An =encrypted= class is encrypted /before/
  push -- a transformation, not a prohibition.  A second remote or bucket was
  considered on 2026-09-17 and is unnecessary under D1: the one bucket stays
  open, content-addressing still works, the only governance surface is key
  distribution.
- D2 :: Split (A) do-not-leak from (B) share-under-a-protocol; build (A).
- D3 :: The software is not a security boundary; enforcement lives in the
  user's legal relationship with the holder.  Cache audience matches grant
  audience, and only the operator knows the tenancy (=data_dir=).
- Terms and the /method of obtaining permission/ live in the data record
  (=SOURCE.org=); /evidence of permission/ for a user lives in that user's
  config.
- Shared-compute is first-class: a pre-warmed shared cache must keep serving
  with no user credentials at all.

** Reversed by EL, 2026-09-17
- The NADA proxy step. :: 09-04 records EL correcting Sue that a WB key

Not a secrets issue -- the passphrase is documented as cosmetic and =CLAUDE.md=

* The class vocabulary
Refines 09-04's four =#+ACCESS_*= keywords.  09-04 put mechanism, class,
protocol and evidence-shape on every wave; that repeats the WB protocol text
104 times and drifts.  Here a wave carries *one* keyword, and a framework
registry carries the rest.

** Per wave: one keyword in =SOURCE.org=
: #+ACCESS_CLASS: wb-nada

=parse_source_org= (=provenance.py:185-238=) already lands unknown =#+KEY:=
lines in =extra=; promote =ACCESS_CLASS= to a field on =WaveProvenance= and
have =render_source_org= write it.  Editing =Documentation/SOURCE.org= moves no
cache hash: =Wave._input_hash= globs =wave_dir= and =_/= non-recursively
(=country.py:933,945,996=), so =Documentation/= is never hashed.  This is the
one cost in the design that is genuinely zero.

** Per file, for GhanaSPS-style mixes: =Documentation/ACCESS.yml=
: # glob relative to Data/, first match wins, default is the wave's ACCESS_CLASS
: - {glob: "dataverse_v1.2/*", class: klps-dataverse-cc0}
: - {glob: "*.dta",            class: unrecorded}

Why not =LICENSE.org=: it is verbatim holder prose (112 files, zero
machine-readable fields, 09-04 measured) and must stay that way so it can be
quoted.  The 10-file CC0 list in GhanaSPS 2017-18's =LICENSE.org= is the
override this file encodes.

** The registry: =lsms_library/access_classes.yml=
Framework-level, a sibling of =derivations.yml=; a new =.yml= moves no cache
hash (=_BUILD_INPUT_SUFFIXES=, =country.py:706=).  One entry per class:

: wb-nada:
:   mechanism: api-key
:   authority: World Bank Microdata Library
:   validate:  {nada_host: microdata.worldbank.org}
:   protocol:  Register at https://microdata.worldbank.org, generate an API key,
:              put it in config.yml as entitlements.wb-nada.api_key
:   evidence:  api_key
: gha-gss-nada:
:   mechanism: api-key
:   authority: Ghana Statistical Service
:   validate:  {nada_host: microdata.statsghana.gov.gh}
:   protocol:  ...
:   evidence:  api_key
: ifpri-dataverse:
:   mechanism: attestation
:   authority: IFPRI / AAU / CSAE
:   protocol:  Read the IFPRI Dataverse Terms of Use at <doi>; non-commercial;
:              then record entitlements.ifpri-dataverse.attested: <date>
:   evidence:  attested
: klps-dataverse-cc0:
:   mechanism: open
: wb-gps-unjittered:
:   mechanism: gpg-recipients
:   authority: World Bank (bespoke permission)
:   protocol:  Obtain written WB permission for the survey; send your public key
:              to <maintainer>; you are added to the recipient set.
:   evidence:  a private key in your keyring that decrypts the blob
: unrecorded:
:   mechanism: unrecorded

*The mechanism is what the gate dispatches on; the authority is what the
evidence must name.* 09-04 said "mechanism, not authority" because one
self-service key was to serve every NADA holder; with that reversed the
authority is part of the class, and =wb-nada= and =gha-gss-nada= are two
classes with one mechanism.

** Four mechanisms, and what each means for the blob
| mechanism        | evidence in user config                  | blob in S3            | gate on a fetch miss                                  |
|------------------+------------------------------------------+-----------------------+-------------------------------------------------------|
| =open=           | none                                     | plaintext             | serve                                                 |
| =attestation=    | =entitlements.<class>.attested: <date>=  | plaintext             | serve if present, else refuse naming =protocol=       |
| =api-key=        | =entitlements.<class>.api_key=           | plaintext             | validate once per process against =validate.nada_host=; refuse naming =protocol= |
| =gpg-recipients= | a private key (optionally =key_id=)      | *ciphertext*, encrypted to every authorized user's public key | fetch ciphertext to L1, =gpg --decrypt=; refuse naming =protocol= if no key matches |
| =unrecorded=     | --                                       | plaintext             | see D5                                                |

The "room for stricter" EL asked for on 2026-09-17 is the fourth row.  Under
the accidental-violation threat model the first three are library-side
if-statements, and D3 says that is all they should be.  The fourth is not:
without a matching private key the bytes are useless, which is enforcement
without a second bucket, an IAM policy, or the library pretending to be a
security boundary.

* =gpg-recipients=: three consequences
EL, 2026-09-17: "secret files gpg encrypted with creds of all authorized
users."  Read as =gpg --encrypt --recipient <pubkey>= for each authorized
user.  No such encryption exists in the tree today -- the two =.gpg= files are
symmetric (=symkey enc packet=; =s3_reader_creds.gpg=, and the unread
=gdrive_data_store.json.gpg= from =4a30e15af=) -- so this is the target, and
D4 confirms it is the intended reading.

- It answers 09-04's Q1 the other way. :: 09-04 proposed a derived nonce so
  re-encryption reproduces the ciphertext (its option (a)).  Asymmetric gpg is
  randomised by construction, and re-encrypting to a *changed recipient set
  should* mint a new blob: the sidecar then pins "the ciphertext readable by
  this authorized set", and revoking a user is a new sidecar plus a commit.
  That is 09-04's option (b), and under recipients it is the mechanism rather
  than a cost.  The cost it does carry: the sidecar md5 is of the ciphertext
  and is folded into every dependent table's build hash, so a recipient-set
  change rebuilds that wave's tables.  Bespoke and rare; acceptable.
- It reintroduces the =gpg= binary that GH #741 removed. :: #741 was a real
  failure (Windows and macOS ship no =gpg=; users saw =NoCredentialsError=
  three layers down).  *Decision proposed: accept it for this class only.*  It
  is bespoke by construction, its users are few and named, and D2 defers
  governance anyway.  The alternative, if EL objects, is a hybrid --
  =cryptography= Fernet data key, wrapped per recipient -- which
  =cryptography= can do without a binary; named here, not designed.
- Decryption needs a private key, and a course server has dozens of students. ::
  D3 handles it: one entitled person decrypts into the shared =data_dir=, the
  plaintext lands beside the ciphertext in L1 (=<md5>.plain=, keyed by the
  ciphertext's md5 so staleness hashing is unchanged), and every later read is
  a warm read.  Which is why the gate goes where it goes:

* Gate placement, and what it costs
** Where
On the *S3-fetch miss branch* of =_ensure_dvc_pulled=, just before the
=get_remote= at =local_tools.py:449=, and at the second =get_remote= site at
=:721=.  Never on =get_dataframe='s warm path, and never at import.  The hot
path stays "two =os.path.exists= calls and a tiny YAML parse" (its own
docstring); the credential-free warm read 09-04 measured (GhanaLSS
=food_acquired=, 5,259,344 rows, no config, no key) is preserved by
construction.  =get_data_file='s DVC branch calls =_ensure_dvc_pulled= since
GH #763, so it inherits the gate; its =permissions(path)= call and the
inverted =resource != "wb_api"= test are removed.

Resolution on a miss: =fn= -> =(country, wave)= (the path parse
=get_data_file= already does at =data_access.py:2110-2113=) -> =ACCESS.yml=
file override, else the wave's =ACCESS_CLASS= -> registry entry -> evidence
in config -> validator (memoised per process per class, as
=_wb_key_validated= already is) -> serve, decrypt, or raise =AccessError=
whose message *is the registry's =protocol= text*.  Never a =403=, never a
=None= (09-04).

The import-time =_auto_unlock_s3()= call goes.  The shared reader blob is
unlocked lazily, on the first miss whose class is not =gpg-recipients=, after
the gate passes.  =LSMS_SKIP_AUTH=1= keeps its meaning -- skip everything, the
operator guarantees =s3_creds= -- which is what the data-free CI job relies
on (=tests/conftest.py:5=).

** Cache-hash cost
GH #763's "no =data_access= symbol reaches any build fingerprint" does not
cover =local_tools._ensure_dvc_pulled=, which is reached from =get_dataframe=
and is *not* in =_build_registry._EXCLUDED_CALLABLES=.  So:
- the gate callable itself (=access.check_fetch= or similar) is excluded on
  the =_assert_built_required_columns= argument: it raises or returns =None=
  and changes no byte of any parquet.  Precedent: the null-read audit's four
  callables, excluded for exactly this reason and pinned by
  =test_the_audit_module_is_not_folded_into_any_build_fingerprint=;
- the one-line call-site edit inside =_ensure_dvc_pulled= is expected to move
  every table's hash once (=CLAUDE.md= Site R: any edit to =get_dataframe='s
  reach moves 37/37).  One corpus re-warm, one time.  *Not measured here* --
  this node has no venv -- measure with the stash-probe before landing.
- Everything else is free: =access_classes.yml= is a new =.yml=,
  =SOURCE.org= is under =Documentation/=, =config.py= is read-path.

** Network cost
=_validate_wb_api_key= is the ~15 s round-trip =902da8352= moved off import.
Under this design it runs at most once per process per class, only on a fetch
miss, only for =api-key= classes.  A user reading from a warm cache pays
nothing; a cold build pays it once.

* Decisions taken (EL, 2026-09-17)
The four questions the first draft left open, resolved the same day.
- D4. =gpg-recipients= means =gpg --encrypt --recipient <each pubkey>=. ::
  Revocation is re-encrypt-without-that-key; there is no passphrase to leak
  or rotate; the keyring is the ACL.  The alternative reading -- one symmetric
  passphrase handed to each authorized user, which is what
  =CONTRIBUTING.org:141-155= does for the reader blob today -- has no
  revocation short of rotating everyone, and is not what is meant.
- D5. =unrecorded= is served, with a warning. ::  GhanaSPS 2013-14 (no
  licence file, GH #140's vintage question) and the 100 pre-existing GhanaSPS
  2017-18 files are read today, and 09-04's "raise an error that names the
  protocol" applied literally would break them.  The gate warns, naming the
  wave and the gap; =LSMS_ACCESS_STRICT=1= refuses -- the same warn/strict
  shape as =LSMS_GRAIN_STRICT= and =LSMS_READ_STRICT=, and the only place in
  this design a strict lever appears.
- D6. The GhanaSPS 2017-18 pre-anonymization files: establish supersession
  first. ::  Done the same day, without a venv, from the Dataverse DDI:
  =slurm_logs/ghana_audit/SUPERSESSION_ghanasps_w3_2026-09-17.org=.  Six of
  the nine YAML-wired files are pre-anonymization copies; *every variable the
  YAML names in all six is present in the public release*.  So they are
  superseded for everything currently wired, and replacing them with the
  public files changes no served column.  The one thing that is not
  superseded is the sub-district geography stripped from =00_hh_info=, which
  nothing reads yet and GH #579 wants for =sample= -- if that is kept, it is
  the first =gpg-recipients= customer already in the bucket.  The terms of
  the 100 files remain unrecorded either way.  (Side finding: the 08-19
  findings doc lists =01fi_employmentmain= as absent from the public release;
  Dataverse v1.2 has it.)
- D7. =attestation= and =api-key= refuse by default. ::  Under the reversed
  proxy a WB-keyed user cold-fetching GhanaLSS needs a GSS key.  The course
  scenario is unaffected -- warm cache, and D8 below -- and a refusal that
  says "register at =microdata.statsghana.gov.gh=" is the accidental-violation
  prevention the design is for.  Refusing was always the stated design for
  =api-key=; it is the whole point for =attestation=.
- D8. A site entitlement layer, not a bypass, for classes. ::  See the next
  section.  EL asked for "a backdoor of sorts to cover things like classes";
  the answer is a place for the operator to state the tenancy that D3 says
  only the operator knows.

* Site entitlements: the class-server case (D8)
The scenario 09-04 made first-class: one instructor, dozens of students on a
shared server, all covered by the instructor's registrations.  The warm cache
handles the common case with no credentials at all (09-04's measurement).
The cold edge -- a student triggers the first fetch of a table -- is where
D7's refusal would bite someone the instructor has in fact covered.

** The mechanism: a third config layer
=config.get()= reads env -> user config -> default (=config.py:83-88=).  Add a
*site* layer between user config and default:

: LSMS_SITE_CONFIG=/shared/course/lsms_site.yml      # or the platformdirs site_config_path default

The site file has the same schema as =config.yml=; its =entitlements:= are
*unioned* with the user's (a user can add, never remove).  The instructor
writes their =wb-nada= and =gha-gss-nada= keys and their =ifpri-dataverse=
attestation there once; the JupyterHub spawner or module file sets the env
var; every student process resolves the gate through the merged view.
Refusal messages are unchanged.  The gate logs which layer supplied the
evidence (=entitlement gha-gss-nada: site=), so the arrangement is visible in
any run's log rather than silent.

** Why this and not a flag
- =LSMS_ACCESS_TRUST_OPERATOR=1= (serve everything) was considered and
  rejected.  It is a gate with no evidence behind it, which is the pattern
  that just failed silently for two years; and it loses the *naming* of which
  entitlement covers whom.  The site layer keeps the evidence and the
  protocol text; it only moves who supplies them.
- =LSMS_CONFIG_DIR= pointed at a shared directory works today but *replaces*
  the user's config rather than layering it, so a student cannot hold a
  personal entitlement alongside the class's.
- It is D3, made concrete: the instructor's API key is readable by the class
  (file permissions are the operator's call), and the instructor's DUA with
  each holder is what covers the students -- the library records the
  arrangement, it does not adjudicate it.

** What it does not cover, by construction
=gpg-recipients= does not layer: a private key is not a config value, and a
class is not a recipient.  For an encrypted wave a class needs, the
instructor decrypts into the shared =data_dir= once (above, "three
consequences"), and the students read warm.  The strict class has no site
bypass, which is the point of having a strict class.

* Phasing
1. *The gate that should have existed* -- =wb-nada= only.  Registry with one
   entry, =ACCESS_CLASS= backfilled to all 135 waves (104 =wb-nada=, 23 by the
   holder table above, 8 after reading their =Documentation/=), gate on the
   miss branch, import-time unlock and =authenticate()= fallback removed,
   =entitlements.wb-nada= aliasing =microdata_api_key=, the site layer (D8).
   Fixes the measured bug; changes nothing for a keyed user; refuses an
   unkeyed cold fetch with the WB protocol text.
2. *The other self-service holders* -- =gha-gss-nada=, =rwa-nisr-nada=, after
   the validator precondition is measured; =ifpri-dataverse= attestation;
   =klps-dataverse-cc0= open; =unrecorded= warn-and-serve (D5).
3. *=gpg-recipients=* (D4) -- for the first customer that is not yet in the
   bucket (09-04: Togo/Novissi 2021, the West African un-displaced GPS).
   Encrypt tool (=scripts/encrypt_to_recipients.py=: recipient list from a
   committed =Documentation/RECIPIENTS= per wave, =gpg --encrypt --recipient=,
