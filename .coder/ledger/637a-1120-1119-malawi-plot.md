## §3 Definitions & conventions in force
- `production_obs`, `reported:<ID>`: `lsms_library/data_info.yml` (Single Index,
  GH #1198); `missing_level_sentinels: crop_production: production_obs:
  unresolved_observation`.
- `unknown_plot` (EPISTEMIC) vs `Farm-level` (STRUCTURAL), and the consumer
  rule "not a plot; two of them are not one plot":
  `lsms_library/data_info.yml` `plot_id:` (registered at `1865cf884`).
- `(not crop-specific)`: `lsms_library/data_info.yml` Index Info
  (`plot_inputs` `crop -> j`, GH #1119, registered at `1865cf884`).
- A missing index value gets the registered sentinel, never NaN: CLAUDE.md
  "Grain Collapse" 3b / Site I.
- Core never aggregates silently; a wave script's own uniqueness claim is
  checked, a repeat raised: Tanzania #1263, CLAUDE.md "Derived Values" (stamp
  after uniqueness).

## §4 Invariants & assumptions
- Malawi Module P codes are offset +1000 and the IHS4/IHS5 Module P recode
  (cassava 100 -> 1001) applies (`_PERENNIAL_RECODE`, GH #869), so the
  library `_crop_code` is not the instrument's code; `production_obs` uses the
  instrument's code and the module letter (raw 1 = maize in G, cassava in P).
- Sales attach on `(i, _crop_code, u)` and the sale-basis ladder; the sale
  module codes are the library codes, so each lumped code's sale lands on its
  own row by construction once the collapse is gone.
- 2010-11 G/P/I/Q/H/D drop exact repeat records first (`drop_repeated_records`,
  GH #637 tail); the 2010-11 frames therefore have non-contiguous indexes, so
  any per-row alignment must be positional (`.values`), as the blocks are.
- 2016-17 / 2019-20 plot keys are `gardenid_plotid`; `format_id` of a blank
  part makes the whole key NaN (41 Module P lines in 2016-17, all with a crop
  code; 2013-14 / 2016-17 / 2019-20 Module D stubs with no labour).
