## §3 Definitions & conventions in force

- `sample` is the single source of `v` (`CLAUDE.md` "`sample()` and Cluster
  Identity"); weights normalised to within-wave mean 1 at API time
  (`country.py:7419`).
- Ethiopia `v` keyspace: `ea_id` W1/W4/W5, `ea_id2` W2/W3
  (`CONTENTS.org` "Cluster (PSU) identifier").
- Panel crosswalk is a committed source, regenerated by `make panel-ids`
  (`CLAUDE.md` "The crosswalk is a committed SOURCE").
- `plot_inputs.j` marker: `(not crop-specific)` (`data_info.yml` Index Info,
  commit `1865cf884`).
- Derived values: a value served under a name implying a different window is
  registered, function = identity (`CLAUDE.md` "Derived Values").

## §4 Invariants & assumptions

- The agriculture cover is HOLDER-grain; a household's rows must agree on EA,
  weight, region and rural code (asserted; 0 disagree).
- Agriculture-cover region / rural labels differ from the household cover's
  for the same codes; the `strata` table knows only the household spellings
  -> decode by code (asserted: every code is used by the household cover).
- W3's agriculture cover carries only `ea_id`; `ea_id -> ea_id2` is ambiguous
  for 2 EAs in the W3 household cover (none holds an ag-only household);
  refuse ambiguity.  ESS2/ESS3 build `household_id2` as `ea_id2` + a 3-digit
  serial (4,954 / 4,954 W3 household rows; 3,779 / 3,779 W2 agriculture rows)
  -> cross-check.
- W3's own `household_id` column is untrusted for linking (`panel_ids.py`
  docstring); W3 links by identity through W2.
- `crop_production`'s W2+ mixed-stand flag was assigned positionally from §9;
  now index-aligned so appended rows cannot shift it.
- Pre-existing: W1 wave frame has 2 duplicated index rows (core collapse,
  lossless) -- unchanged.

## §6 Open questions for the human

- **The window key's name on W1 rows.**  `permanent-crop-12-month-window` now
  also labels W1 §12 Q3 harvests, and W1 §12's roster includes root crops and
  vegetables (2,040 of the 3,740 unique-field lines' §4 rows say "not a tree
  fruit crop": garlic, leafy greens, potato...).  The key records the WINDOW,
  and its rule says so; whether the name should become crop-neutral is a
  naming decision (it would rename a key served on W4/W5 rows too).
- **`cluster_features` coverage of the new `v`s.**  Households from the
  agriculture cover sit in 1 / 1 / 6 / 3 EAs (W2-W5) with no household-cover
  row, so those `v` join no `cluster_features` row (`market=` lookups give
  NA).  The agriculture cover carries region / zone / woreda for them; adding
  those EAs to `cluster_features` is outside D1's ruling.
