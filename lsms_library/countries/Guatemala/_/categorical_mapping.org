* Educational attainment (GH #493)

Guatemala ENCOVI 2000 records highest education in the P07 (education)
section of =ECV09P05.DTA=, Q27 "ultimo grado aprobado":

- =p07b27a= (nivel) is value-labelled in Stata: ninguno / preparatoria /
  primaria / educacion media / educacion superior / post-grado /
  educacion adultos.  Code 9 is unlabelled (33 cases, scattered ages) and
  is treated as Unknown.
- =p07b27b= (grado) is the highest year passed within that level.

This table maps the *bare* Stata value-labels of =p07b27a= onto coarse
canonical levels.  The =individual_education(df)= df_edit hook in
=guatemala.py= then *refines* the two grade-dependent levels using
=p07b27b= (grado), which the bare nivel label cannot express:

- "primaria" is a 6-year cycle: the table maps it to *Primary complete*;
  the hook downgrades grado 1-5 to *Primary incomplete*.
- "educacion media" spans the *ciclo basico* (lower secondary, media years
  1-3) and the *ciclo diversificado* (upper secondary, media years 4-6).
  The table maps it to *Lower secondary*; the hook promotes grado 3 ->
  *Lower secondary complete*, grado 4-5 -> *Upper secondary*, grado 6+ ->
  *Upper secondary complete*.
- "educacion adultos" is non-graded adult literacy/equivalency -> Informal.
- "educacion superior" is degree-track university -> Bachelor (the survey
  does not separate a non-degree tertiary diploma here); "post-grado" ->
  Postgraduate.
- nivel code 9 is unlabelled in Stata, so it reaches the mapping as the
  float-string "9.0" (and "9") -> Unknown.

Only the Guatemala-specific Spanish labels appear below; canonical
identity rows and English variants are inherited from the global base
=lsms_library/categorical_mapping/harmonize_education.org= (so the hook's
refined outputs such as "Primary incomplete" pass through unchanged).

* harmonize_food (the j axis) -- migrated from food_items.org (GH #783)

Canonical country-level food-item label table for the =j= axis, migrated
verbatim from the retired standalone =_/food_items.org= by GH #783 -- the
same "Unit #0" migration Tanzania and Ethiopia already completed
(=slurm_logs/2026-06-13_wb_incidence_map/PARITY_LOOP_DESIGN.md=).

*Guatemala's table had no =#+name:= at all*, so =all_dfs_from_orgfile=
returned nothing for it and it was unreachable by *every* name-keyed
mechanism -- =Country.categorical_mapping= (which never opens
=food_items.org= under any name), the =mappings:= syntax in
=data_info.yml=, and =labels== alike.  Its two readers reached it only by
passing =name=None= to =df_from_orgfile=, i.e. "the first table in the
file", which works only while the file holds exactly one table.  Naming it
was a prerequisite for the move.

*Columns -- all three carried across unchanged:*
- =Preferred Label= :: canonical cross-survey English label; the key
  =_relabel_j= renames FROM and =_/fct.py= indexes on.
- =2000= :: the raw Spanish item text from ENCOVI 2000, the join key used
  by =2000/_/food_acquired.py=.
- =FCT code= :: the food-composition-table key consumed by =_/fct.py=
  (note the lower-case "code" -- =labels='FCT code'= is the spelling that
  resolves).

Readers repointed here: =_/fct.py= and =2000/_/food_acquired.py=, plus the
=_/Makefile= prerequisites that used to name =food_items.org=.

*Not to be confused with =guatemala.py::harmonized_food_labels=*, which
names a DIFFERENT file -- =../../_/food_items.csv= -- that does not exist
anywhere in the tree.  That function is dead and is left alone here; GH
#783's issue body explicitly scopes it out.

No wave declares its own =harmonize_food=, so nothing shadows this table.
No =Aggregate Label=: Guatemala never had one and GH #783 does not invent
one (that needs the CFE beta-spread test).
