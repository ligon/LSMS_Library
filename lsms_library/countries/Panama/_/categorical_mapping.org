#+title: Panama categorical mappings

This file is NEW as of GH #783.  Panama previously had no country-level
=categorical_mapping.org= at all; its food vocabulary lived in a standalone
=_/food_items.org= that =Country.categorical_mapping= never opens under any
table name, so =labels== (=Country._relabel_j=) raised
=LabelUnavailableError= for this country.

* harmonize_food (the j axis) -- migrated from food_items.org (GH #783)

Canonical country-level food-item label table for the =j= axis, migrated
verbatim from the retired standalone =_/food_items.org= -- the same "Unit
#0" migration Tanzania and Ethiopia already completed
(=slurm_logs/2026-06-13_wb_incidence_map/PARITY_LOOP_DESIGN.md=).

*Panama's table had no =#+name:= at all*, so =all_dfs_from_orgfile= returned
nothing for it: the ~81 labels were unreachable by *every* name-keyed
mechanism, not just =categorical_mapping= but the =mappings:= syntax in
=data_info.yml= too.  All three wave scripts reached it by passing
=name=None= to =df_from_orgfile=, i.e. "the first table in the file" -- which
works only while the file holds exactly one table.  Naming it was a
prerequisite for the move, and is why every repointed reader now passes
=name='harmonize_food'= explicitly.

*Columns -- all five carried across unchanged, in their original order:*
- =Preferred Label= :: canonical cross-wave label (Spanish, title-cased);
  the key =_relabel_j= renames FROM.
- =2008= :: the raw lower-case product text from ENV-08; join key for
  =2008/_/food_acquired.py=.
- =2003= :: the raw mixed-case product text from ENV-03; join key for
  =2003/_/food_acquired.py=.
- =1997= :: the numeric product code from ENV-97; join key for
  =1997/_/food_acquired.py=.
- =FCT ID= :: the INCAP Central-American food-composition-table key
  (=_/central_american_fct - FCT.csv=), prepared by Kaylee Vu against
  http://www.incap.int/mesocaribefoods/dmdocuments/TablaCAlimentos.pdf.

The regeneration recipe for this table (a =read_sheets= call against the
Google Sheet =1YwfdL0LMPVl3UGo-KfyvpC7S7KR_jDL54rsVLUQOCVE=) is preserved
in =_/CONTENTS.org= under "food_items.org", together with the earlier rough
version.  That recipe writes =food_items.csv=; if it is ever re-run, its
output must now be folded into THIS table rather than into a standalone
file, or the vocabulary becomes invisible again.

No wave declares its own =harmonize_food=, so nothing shadows this table.
No =Aggregate Label=: Panama never had one and GH #783 does not invent one
(that needs the CFE beta-spread test -- see
=.claude/skills/add-feature/food-acquired/SKILL.md=).  =CONTENTS.org='s
"Rough Version" section says the table /should/ have Aggregate Labels; that
remains an open TODO, not something this migration silently supplied.
