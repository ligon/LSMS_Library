#+title: Categorical mappings for GhanaSPS

* Educational attainment (GH #171)

Maps the GSPS grade and qualification labels onto the canonical ordinal
vocabulary in =lsms_library/categorical_mapping/canonical_education_labels.org=.
Row-additive over the global base in
=lsms_library/categorical_mapping/harmonize_education.org= (=harmonize_education=
is in =country._ADDITIVE_CATEGORICAL_TABLES=), so only GSPS-specific labels and
GSPS spellings are listed here; country rows win on key collision.

*ONE table serves TWO source variables.*  =individual_education= reads the
grade ladder (=s1fi_3= / =highestgrade=) and, as a fallback, the qualification
ladder (=s1fi_4= / =highestqual=) -- see the =data_scheme.yml= comment for why
both are needed.  Every label below is unique to one ladder or means the same
thing in both (=Masters= grade / =Master's= qual both -> =Postgraduate=;
=Vocational/Commercial= grade / =Voc/Comm= qual both -> =Vocational/Technical=),
so a single table is unambiguous.  Check that before adding a row.

*Map on the DECODED LABEL, never on the numeric code.*  The codes diverge
between waves while the labels do not: code 27 is ='S1'= in 2009-10 and
2013-14 but ='SSS4'= in 2017-18, and every code above 26 is shifted by one in
wave 3.  =get_dataframe= decodes the Stata value labels, so this table keys on
the label and the divergence is harmless -- but a mapping written against the
codes would be silently wrong for one wave in three.

*Case and punctuation matter*: the lookup is an exact dict lookup
(=df_data_grabber= does =df[col].map(lambda x: f.get(x, x))=), and an unmapped
label PASSES THROUGH RAW rather than becoming NA.  The three waves spell the
same category three ways (='Pre-School'= / ='Preschool'= / ='Pre-school'=;
='GCE O Level'= / ="GCE 'O' level"=), so each spelling needs its own row.

** Two rulings worth recording

1. =Level 100= .. =Level 400= are Ghanaian *university* year designations.
   The sibling survey has two precedents that point different ways --
   =GhanaLSS/_/categorical_mapping.org= maps its GLSS7 =Year one..three= ->
   =Tertiary certificate/diploma= and =Year four/five= -> =Bachelor= (a
   commented, deliberate decision covering tertiary years generically), but
   maps its GLSS1-3 letter-ladder =U1..U4= (University years 1-4) ->
   =Bachelor=.  We follow the *commented* convention: 100/200/300 ->
   =Tertiary certificate/diploma=, 400 -> =Bachelor=.  It keeps an in-progress
   year below the completion rung, which is how the canonical vocabulary
   already treats partially-completed primary and secondary cycles (=P1..P5=
   -> =Primary incomplete=, =SSS1..SSS2= -> =Upper secondary=), and the
   canonical ladder has no "tertiary incomplete" rung to use instead.
   Affects 22 rows at Levels 100-300 and 54 at Level 400, all in 2009-10.

2. =L6= / =U6= are Lower and Upper Sixth Form, which in the old Ghanaian
   system follow =S1..S5= and lead to GCE A-Level; both -> =Upper secondary
   complete= (37 rows, 2017-18 only).  NOTE: =GhanaLSS/_/categorical_mapping.org=
   contains =U6= *twice with conflicting targets* -- =Upper secondary complete=
   in its case-duplicated block and =Postgraduate= in its GLSS1-3 letter-ladder
   block, where =U= means University rather than Upper Sixth.  Per-country
   tables do not leak across countries, so that defect cannot reach GhanaSPS;
   it is recorded here because it is a real ambiguity in a sibling file and
   should be fixed there, not silently inherited.

* Roof / Floor (housing)

These two tables are auto-discovered by ~Country._apply_categorical_mappings~
(the table name matches the column name, case-insensitively) and applied at
API time to ~housing.Roof~ / ~housing.Floor~.  They are NOT baked into the
cached parquet, so the raw survey labels remain recoverable from
~{data_root}/GhanaSPS/*/_/housing.parquet~.

The ~Preferred Label~ column is drawn ENTIRELY from the shared vocabulary in
=lsms_library/categorical_mapping/canonical_housing_labels.org= (GH #170).
No new canonical label is coined here: Uganda and Malawi both emit only
canonical values, and a country that invents one defeats the point of the
shared list.  Delivered value sets:

  Roof  : Iron Sheets, Thatch, Asbestos, Concrete, Clay Tiles, Mud, Wood, Other
  Floor : Earth, Concrete, Tiles, Vinyl/Linoleum, Bricks, Stone, Wood, Other

** Two jobs, and the first one is the load-bearing one

*** 1. Cross-wave drift WITHIN GhanaSPS

The GSPS roof/floor code frames are identical across the three waves (same
codes 1-8, same materials), but the Stata value LABELS are re-typed each
wave.  The drift is punctuation and wording, not case -- so the case
normalisation the ~housing~ sub-skill describes would not have caught it:

| code | 2009-10                   | 2013-14                   | 2017-18                   |
|------+---------------------------+---------------------------+---------------------------|
|    3 | Corrugate iron sheets     | Corrugated iron sheets    | Corrugated iron sheet     |
|    1 | Palm leaves/Raffia/Thatch | Palm leaves/raffia/thatch | Palm leaves/raffia/thatch |
|    7 | Mud bricks /Earth         | Mud bricks/earth          | Mud bricks/earth          |
|    9 | Other                     | Other - specify (95)      | Other (please specify) (-666) |

Note code 3 in wave 1 is "Corrugate", not "Corrugated" -- a source typo --
and wave 3 drops the plural.  Three spellings of the modal roof material.
Floor is the same story: wave 1's code 4 is =Cement/ concrete= with an
INTERNAL space after the slash, and its code 8 is =Terrazo= with one z.
Internal whitespace survives ~.str.strip()~, so both must appear verbatim.

*** 2. Mapping GSPS's categories onto the canonical vocabulary

Every judgement made, and its basis:

- =Corrugate(d) iron sheet(s)= -> *Iron Sheets*.  Canonical roof label,
  "Most common across LSMS-ISA"; Uganda maps =Iron sheets=/=Tin= to it.
- =Palm leaves/raffia/thatch= -> *Thatch*.  Canonical "dried plant
  material"; Malawi maps =Grass= to it, Uganda =Thatch, Straw=.
- =Cement/concrete= (roof AND floor) -> *Concrete*.  The canon deliberately
  keeps =Cement= and =Concrete= distinct, but GSPS offers ONE combined
  option, so the distinction is not recoverable for Ghana.  Uganda's tables
  resolve the identical compound (=Concrete/cement=, =Concrete/ Cement=) to
  =Concrete= in both its Roof and Floor tables; that precedent breaks the
  tie.  For a roof this is also unambiguous on the merits (a cement-screed
  roof is not a thing); for a floor a Ghanaian "cement/concrete" floor is
  more often a screed, so this call is precedent-driven, not physical.
- =Asbestos/slate= -> *Asbestos*.  The canon carries BOTH =Asbestos= and
  =Slate= (the latter added for Tajikistan), and GSPS lumps them into one
  option.  Asbestos (fibre-cement) sheet is the common Ghanaian roofing of
  the two; slate roofing is essentially absent.  NOT verified against the
  questionnaire -- the instrument prints the same compound option.
- =Roofing tiles= -> *Clay Tiles*.  GSPS does not say "clay", but the canon
  has no generic roof-tile label and Uganda maps its own unqualified
  =Tiles=/=tiles= to =Clay Tiles=.  Exact precedent.
- =Mud bricks/earth= -> *Mud*.  Canonical =Mud= is documented as
  "Includes Adobe (sun-dried mud brick)", which is this category.
- =Bamboo= -> *Bamboo* (since 2026-09-02, GH #727; was *Wood*).  The canon
  now carries =Bamboo= as its own roof label, so the one merge this file
  used to make is gone.  The RESOLVED caveat below keeps the history.
- =Earth/mud/mud bricks= -> *Earth*.  Canonical, matching Uganda
  (=Rammed earth=) and Malawi (=Smoothed mud=).
- =Ceramic/marble(/) tiles= -> *Tiles*; =Vinyl tiles= -> *Vinyl/Linoleum*.
  The canon's separate =Vinyl/Linoleum= label ("resilient sheet/tile
  flooring (linoleum, vinyl, vinyl tiles)") is what keeps these two GSPS
  categories from colliding on =Tiles=.  Without it this would have been a
  merge.
- =Burnt bricks= -> *Bricks*.  Canonical floor label.  Note GSPS's
  =Earth/mud/mud bricks= is the UNFIRED brick category and goes to =Earth=,
  so the two brick categories stay apart.
- =Terrazo=/=Terrazzo= -> *Terrazzo* (since 2026-09-02, GH #727; was
  *Stone*).  The canon now carries =Terrazzo= as its own floor label, so
  GSPS's =Stone= (17-18 rows/wave) and its terrazzo (16-18 rows/wave) no
  longer merge.  SUPERSEDED reasoning for the old target, kept for the
  record: it was THE WEAKEST CALL IN THIS FILE.  The canon had no
  terrazzo label, and every available canonical label merged
  terrazzo with some other GSPS floor category: =Concrete= merges it with
  the 4,673-row =Cement/concrete=, =Tiles= with =Ceramic/marble tiles=,
  =Other= with GSPS's own =Other=.  =Stone= is documented as "Includes
  polished stone / marble", which is literally what terrazzo is (marble
  chips in cement, ground and polished), and it keeps terrazzo among the
  premium floors for welfare work.  It merges with GSPS's =Stone= (17-18
  rows/wave).  Recorded as a judgement, not a fact.
- =Other= / =Other - specify= / =Other (please specify)= -> *Other*.

*** CAVEAT (RESOLVED 2026-09-02, GH #727): Bamboo -> Wood was a real merge, and GSPS is why the canon changed

RESOLVED 2026-09-02: =Bamboo= (roof and floor) and =Terrazzo= (floor) were
added to =canonical_housing_labels.org= under GH #727, and the =Bamboo=,
=Terrazo= and =Terrazzo= rows below now target them (29 / 7 / 8 bamboo
roofs and 0 / 16 / 18 terrazzo floors by wave move out of =Wood= and
=Stone=; nothing else moves).  The caveat as originally written follows,
kept as the record of why the canon changed.

GSPS's roof question offers *Wood* (code 2) and *Bamboo* (code 8) as
SEPARATE options -- 20/10/11 and 29/7/8 observations respectively across
the three waves.  The canonical vocabulary folds bamboo into =Wood=, so
the two collapse.  That is a genuine loss of a distinction the survey drew,
and it is the only such loss in this file.

It is done anyway because unilaterally coining a canonical label in a
country-wiring change would break the invariant that makes
=canonical_housing_labels.org= worth having.  The loss is mitigated: the
mapping is applied at API time only, so ~pd.read_parquet~ on the cached
housing parquet still shows =Bamboo=, and ~s12a_32~ / ~materialroof~ in
the source are untouched.

RECOMMENDATION (DONE under GH #727, 2026-09-02) for whoever owns GH #170:
add *Bamboo* (and possibly *Terrazzo*) to the canonical roof/floor lists
and re-point the two rows below.  GhanaSPS appears to be the first country
in the corpus whose roof question separates bamboo from wood.

*** What is deliberately NOT mapped

- Wave 3 declares the sentinels -999 "Don't know", -888 "Refuse to answer"
  and -777 "Not applicable" on both variables.  NONE of them occurs in the
  data (checked on the shipped file), so no row is written for them.  If a
  future extract carries one it will pass through unmapped and show up as a
  non-canonical value -- which is the correct, loud outcome.  (-666 DOES
  occur and is just wave 3's spelling of "Other".)
- Outer wall (=s12a_30= / =materialouterwall=) is present in every wave and
  is deliberately not wired: the `housing` schema is Roof + Floor only.

*** How this fails silently, and why the test is a subset assertion

~_apply_categorical_mappings~ applies ~Series.replace(rdict)~, which leaves
an unmatched value UNCHANGED rather than nulling it.  So a missing or
mistyped Alternate Spelling does not raise and does not show up as a null --
the raw label simply survives into the delivered table.  The discriminating
check is therefore "is the delivered per-wave value set a SUBSET of the
canonical set above", never "do the distributions look plausible".

* Plot features: AreaUnit / Tenure (GH #732, #729)

Two tables for =plot_features=.  Unlike =Roof= / =Floor= above, these are
referenced EXPLICITLY from each wave's =data_info.yml=
(=mappings: ['Tenure', 'Alternate Spelling', 'Preferred Label']=) and so are
applied at EXTRACTION time: the cached =plot_features.parquet= already carries
the canonical values.  That is deliberate -- =tests/test_table_structure.py=
runs the declared-spellings check on the cached parquet, and =Tenure= has a
declared vocabulary in =lsms_library/data_info.yml=, so an API-time mapping
would leave the parquet failing a check the delivered table passes.  Because
the table names also match the column names,
~Country._apply_categorical_mappings~ applies them a SECOND time at API time;
that pass is idempotent (no Preferred Label below is also somebody else's
Alternate Spelling), and it is what would repair a parquet written before a
row was added.

* Livestock: harmonize_species (GH #729, #736)

The =livestock= table's =animal= index level carries the =Preferred Label=
from this table.  It is the corpus name (Uganda, Nigeria and Malawi each
keep a =harmonize_species= table) and it is applied at EXTRACTION -- every
wave's =data_info.yml= references it with
=mappings: ['harmonize_species', 'Alternate Spelling', 'Preferred Label']=
on the =animal= idxvar -- so the cached parquet is already canonical.  The
lookup is an exact dict lookup on the decoded source label, and an unmatched
value passes through UNCHANGED (it is not nulled and nothing raises), so the
discriminating test is "is the delivered per-wave value set a subset of the
Preferred Labels plus the listed pass-throughs", never "does the
distribution look plausible".

** Three instruments, three vocabularies

- 2009-10 =S3AI.dta= :: =animal_id= is a labelled categorical with eight
  values: =Drought Animal= (sic), =Cattle=, =Sheep=, =Goats=, =Pigs=,
  =Rabbits=, =Chicken/Rosters=, =Other Farm Animals=.  The last is a
  catch-all the instrument never asks to name, and 20 households list it on
  two or three lines.
- 2013-14 =03ai_animalquestions.dta= :: a FIXED seven-species grid asked of
  every household (lower-case: =draught animals=, =cattle=, =sheep=,
  =goats=, =pigs=, =rabbits=, =chickens=), plus a 174-row "other" tail whose
  =animal= is FREE TEXT -- 62 distinct spellings, 26 of them guinea fowl
  (=GINUEA FOWL=, =GUINNEA FOWL=, =gueni folws=, =GUINE  FOWL= with two
  internal spaces, ...).
- 2017-18 =03ai_animalquestions.dta= :: eight clean labels (=Cattle=,
  =Sheep=, =Goats=, =Pigs=, =Rabbits=, =Chickens/roosters=, =Draught animal
  (donkey, horse, bullock)=, =Fish=); its =_osp= "other -- specify" sibling
  carries eleven title-case free-text species.

** The rule: harmonise the SPELLING, never fold a SPECIES

A precedent label wins wherever one exists -- Uganda's species-level
=Cattle= / =Sheep= / =Goats= / =Pigs= / =Rabbits= / =Chicken= / =Donkeys= /
=Other Poultry=, and Nigeria's and Malawi's =Guinea Fowl= / =Duck= / =Turkey=
/ =Fish= / =Dove/Pigeon= / =Other Livestock= -- so that =Feature('livestock')=
agrees across countries on every label that has one.  That is why the list
mixes plurals with a singular =Duck= and =Turkey=: cross-country
coincidence was preferred to internal tidiness.  Where no precedent exists
the coinage is plural: =Draught Animals=, =Dogs=, =Cats=, =Grasscutters=,
=Guinea Pigs=, =Peacocks=, =Quails=.

Only a label that names NO species goes to a catch-all: =BIRDS= / =Bird= to
=Other Poultry=, =Other Farm Animals= to =Other Livestock=.  Ducks, turkeys
and guinea fowl are NOT folded into =Other Poultry= -- the respondent named
them, and Nigeria and Malawi keep them distinct.  Dogs and cats are reported
with sale values in waves 2 and 3 and are kept under their own labels rather
than hidden inside =Other Livestock=, so an analyst can exclude them from a
wealth aggregate.

Note the consequence for cross-wave reading: wave 1's =Other Farm Animals=
catch-all is where its guinea fowl, ducks and turkeys live (the instrument
offered no other slot), while waves 2 and 3 name them.  =Other Livestock=
therefore exists only in 2009-10, and a wave-over-wave comparison of =Guinea
Fowl= or =Other Livestock= is an instrument artefact.  Likewise =Donkeys=
(named in the free text) overlaps conceptually with =Draught Animals= (the
grid row that includes donkeys); a household that wrote "donkey" in the
other slot is delivered as =Donkeys=, as reported.

** Three spellings are left UNMAPPED, deliberately

='50'= (a number typed where a species should be), ='cut'= (cat?) and
='dake'= (duck?) each occur once in 2013-14.  They are genuinely
unmappable -- a guess would be a fabrication -- so they are not in the table
and pass through as their own =animal= values.  ='50'= is also excluded
because the org parser coerces an all-numeric column cell to a number, so a
row for it would never match the string anyway.

Every Alternate Spelling appears exactly once: =set_index().to_dict()= keeps
the LAST row on a duplicate key, so a spelling shared by two waves
(=Guinea Fowl=, =Turkey=, =Dog=, =Cat=, =Donkey=, =Grasscutter=) has one row.

* Crop production: harmonize_crop / harvest_units (GH #729, #140)

Two tables for =crop_production=.  Both are applied at EXTRACTION: the
2013-14 and 2017-18 =data_info.yml= blocks reference them with
=mappings: ['harmonize_crop', 'Alternate Spelling', 'Preferred Label']= on
the =j= idxvar and =mappings: ['harvest_units', ...]= on the =u= idxvar (and
on the nine 2017-18 sale-channel unit columns), and the 2009-10 wave script
applies =harmonize_crop= to the decoded crop label itself.  The lookup is an
exact dict lookup on the DECODED label -- never on the numeric code, because
the codes are not stable (2017-18 introduces =-666= for "Other", and 2013-14
ships two rows whose =cropcode= is blank) -- and an unmatched value passes
through UNCHANGED, so the discriminating test is "is the delivered per-wave
=j= / =u= set a subset of the Preferred Labels", never "does the top-10 look
right".  Neither table is named after a column: a table named =u= would be
auto-dispatched at API time onto EVERY table with a =u= level
(=food_acquired= included) and row-unioned with the global
=categorical_mapping/u.org=, which is not wanted here.

** harmonize_crop

The rule, in order: (1) the GhanaSPS =food_items.org= Preferred Label where
the harvested crop IS that food item, verbatim (=Maize=, =Cocoyam=,
=Groundnuts=, =Onions=, =Orange/Tangerine=, =Pepper (fresh or dried)=,
=Tomatoes (fresh)=, =Palm Nuts= for oil palm, whose harvested part is the
fruit/nut in 488 of 502 wave-1 records) -- this is Uganda's stated purpose
for its =harmonize_crop= (a crop =j= joins =food_acquired.j=), and GhanaSPS
has no coarser Aggregate column to prefer; (2) otherwise Uganda's
=harmonize_crop= label where the crop exists there (=Beans=, =Cocoa=,
=Coffee=, =Cotton=, =Rice=, =Other Crop=); (3) otherwise a title-case coinage
(=Cashew Nuts=, =Kenaf=, =Leafy Vegetables=, =Sheanuts=, =Tiger Nuts=,
=Potatoes/Sweet Potatoes=, =Other Food Crops=).  Spelling is harmonised; no
crop is folded into another.  Three instruments, three spelling systems:
2009-10 title-case value labels (=Groundnut/Peanut=, =Water melon=), 2013-14
lower-case free-ish text (=groundnut/peanut=, =oranges/ tangerine= AND
=oranges/tangerine=, =papaya= AND =pawpaw=, =soya bean= AND =soya beans=,
=pepe= for pepper, =potatoes/sweet potat= truncated), 2017-18 title-case with
its own typography (=Groundnut/ Pea nut=, =Guinea= truncated from Guinea
corn/Sorghum, =Garden egg/egg=, =Pawpaw/papaya=, and =Other= for its =-666=
catch-all).  Every spelling appears exactly once.

2009-10 records the PART harvested (A80.2: "e.g. Cocoa, Cocoa Leaves"); the
wave script qualifies =j= where the part is a different product from the
crop's principal one (=Cocoyam Leaves=, an existing =food_items= label; else
=Crop (part)=).  Those labels exist ONLY in 2009-10 -- see
=ghanasps.product_label= and the data_scheme.yml block.

* Plot labour: harmonize_stage / harmonize_labor_source / WageUnit (GH #729, #140)

The =plot_labor= index is =(t, i, plot_id, season, stage, source)=.  All three
waves are wave scripts, so each script emits the Preferred Label directly
(mirroring =harmonize_species=); these tables are the canonical REGISTRY for
the three vocabularies, and =WageUnit= additionally auto-dispatches at API time
onto the column of the same name (idempotent -- every Preferred Label is its
own Alternate Spelling).

** harmonize_stage -- the =stage= index level

*Nine values, and the reason there are nine rather than four or seven.*  The
2009-10 instrument asks the labour battery FOUR times per season; 2013-14 and
2017-18 ask it SEVEN times.  The later seven are not a refinement of the same
four: 2009-10's blocks are strictly COARSER, and its first block is not a
subset of anything in the later list.  So neither vocabulary can be dropped
without inventing data, and folding the later waves onto the earlier four
would throw away grain the survey collected.  Both are kept, exactly as each
instrument asked them, and the containment is recorded here so a consumer can
fold in the one direction that is sound (7 -> 4, by summing =PersonDays=):

| 2009-10 (4, coarse)             | 2013-14 / 2017-18 (7)                             |
|---------------------------------+---------------------------------------------------|
| =land_preparation=              | =clearing_and_land_preparation= + =ploughing= + =planting= |
| =field_management=              | =chemical_application= + =weeding=                |
| =harvesting=                    | =harvesting=                                      |
| =post_harvest=                  | =post_harvest=                                    |

The 2009-10 blocks are named ONLY in the questionnaire
(=2009-10/Documentation/Household_questionnaire_Part_A.pdf=, Section 4
"IX. LABOR INPUTS"), whose eight section headers read verbatim:

- A290--A298 / A327--A335 :: "THE FOLLOWING QUESTIONS PERTAIN TO LABOR USE ON
  LAND PREPARATION E.G. CLEARING OR WEEDING BEFORE PLANTING, SEEDING/NURSERY,
  PLANTING AND TRANSPLANTING DURING THE MAJOR [MINOR] SEASON:"
- A299--A307 / A336--A344 :: "THE FOLLOWING QUESTIONS PERTAIN TO LABOR USED ON
  FIELD MANAGEMENT (WEEDING AFTER PLANTING, FERTILIZED AND PESTICIDE
  APPLICATIONS, IRRIGATION, MANAGEMENT ETC DURING THE MAJOR [MINOR] SEASON:"
- A308--A316 / A345--A353 :: "THE FOLLOWING QUESTIONS PERTAIN TO LABOR USED ON
  HARVESTING OF CROPS DURING THE MAJOR [MINOR] SEASON:"
- A317--A325 / A354--A362 :: "THE FOLLOWING QUESTIONS PERTAIN TO LABOR USED ON
  POST-HARVEST ACTIVITIES (INCLUDING PRESERVATION FOR STORAGE ETC) OF CROPS
  DURING THE MAJOR [MINOR] SEASON:"

*=ploughing= is the one placement the 2009-10 header does not settle.*  It
names clearing, weeding-before-planting, seeding/nursery, planting and
transplanting, and does not mention ploughing -- but neither does it exclude
it, whereas 2013-14 and 2017-18 explicitly DO ("Activities such as plowing,
tilling, or mound-making should NOT be included as land preparation"), which
is why they need a separate stage for it.  Hoe ploughing therefore has nowhere
else to go in 2009-10 and the fold above puts it in =land_preparation=; that
one cell is a reading, not a quotation, and is flagged as such.

2017-18's instrument prints the stage definitions in full ("Ploughing: Hoe
ploughing only.  This does not include any tractor activities."); the data
label spells it =Plowing=, 2013-14's spells it =ploughing=.  Both fold to
=ploughing=.
