* Relation to head

** GLSS1 fourteen-code list (=relationship_glss1=)

GLSS1's (1987-88) relationship-to-head code list, from that wave's own data
dictionary: https://microdata.worldbank.org/index.php/catalog/2313/data-dictionary/F184?file_name=y01a
Verified against the raw data for GLSS1 and GLSS2 (=REL= takes codes 1-14;
code 1 occurs 3,136 / 3,192 times = each wave's household count).  Read by
=1987-88/_/mapping.py= and =1988-89/_/mapping.py= via
=code_label_map('relationship_glss1', _dirs)=.  GLSS3 and GLSS4 use a
different NINE-code list and carry their own wave-level =relationship=
tables (CONTENTS.org Trap 2).

Renamed from =relationship= on 2026-09-07 (GH #797), for two reasons:
1. The framework auto-applies any country table named after a served column
   (=Relationship=), and =relationship= is now the name of the LABEL
   harmonization table below.  A =| Code | Label |= table under that name was
   never a mapping (=_build_replace_dict= needs a =Preferred Label= column),
   but the two would collide by name.
2. Trap 2's mechanism.  GLSS3 was decoded through this table for its whole
   life (GH #799) because a wave-first =code_label_map= search found no wave
   table and fell through to here.  With this table no longer answering to
   =relationship=, a wave that lacks its own =relationship= CODE table gets
   ={}= from =code_label_map= (the harmonization table below has no =Code=
   column, so the lookup raises =KeyError= there and moves on) and ships a
   100%-null =Relationship= that the Site B null-read guard reports loudly --
   instead of a silently mis-decoded one.  A fallback that has never been
   exercised has never been checked (Trap 4); this one can no longer be
   exercised at all.

** Label harmonization (=relationship=): one vocabulary for seven waves

Applied AUTOMATICALLY by =Country._apply_categorical_mappings= to the
=Relationship= column of any table that carries one (here =household_roster=),
at API time on EVERY read, warm or cold: the column is =.str.strip()=-ed and
=.replace()=-d through =Original Label -> Preferred Label=.  The cached
parquets (L2-wave and L2-country) keep the RAW strings.  Since =df9baf91=
(GH #797) the kinship expansion (=Generation= / =Distance= / =Affinity=)
runs AFTER this mapping, so it sees the Preferred Label.  The seven waves
used to serve five vocabularies (32 distinct strings); they now serve one
(17 labels).

Column order is load-bearing: =_build_replace_dict= keys on the FIRST column
that is not =Preferred Label=, so the raw label comes first.  The Original
Label is the SERVED string -- after the wave/country formatter: the country
formatter =_/ghanalss.py:Relationship= title-cases 2012-13 and 2016-17, and
2005-06's wave formatter title-cases too -- NOT the =.dta= value label
(=Child (Son/daughter)= in the file is =Child (Son/Daughter)= here).

Identity rows are deliberately ABSENT: =.replace()= leaves unmatched values
alone, so a label that is already canonical (Head, Spouse, Child, Grandchild,
Parent, Sibling, Niece/nephew, Other relative, Servant, Tenant) needs no row.
Do not add them.

The vocabulary is ONE list shared with GhanaSPS (its country table maps onto
the same labels; decided with @ligon 2026-09-07 -- a Ghana vocabulary, not a
corpus one, because surveys elsewhere understand relationships differently):
Head, Spouse, Child, Adopted/foster/stepchild, Child-in-law, Grandchild,
Parent, Parent-in-law, Sibling, Sibling-in-law, Niece/nephew, Other relative,
Non-relative, Servant, Tenant.  Every one is a =kinship.yml= key (the lookup
tries =.title()= first: =Parent-in-law= -> =Parent-In-Law=).

Tuple-preserving BY CONSTRUCTION, with ONE stated exception: every Original
Label and its Preferred Label resolve to the same kinship tuple under
=_expand_kinship='s lookup, checked on all 246,594 rows -- except the adopted
row.  =Adopted Child= (GLSS5/6, 963 people; was [-1,0,consanguineal]) and
=Adopted / Foster/ Step Child= (GLSS7, 501; was [-1,0,step]) are one label,
=Adopted/foster/stepchild=, whose tuple is [-1, 0, null]: a child of the
head, but whether by adoption, fostering or a step relation the instruments
do not agree and the ontology has no =adoptive= affinity, so Affinity is
null (the GH #698 shape, same as =Other relative='s Generation/Distance).
Other decisions the table encodes:
- =Parent/Parentlaw= (GLSS5/6) and =Parent/Parent-In-Law= (GLSS7) are ONE
  survey code conflating parent and parent-in-law; served as =Parent= (tuple
  unchanged); the conflation is recorded in CONTENTS.org like GLSS3+'s =Other
  relative= absorbing siblings.  GLSS1/2's separate =Father/mother in-law= is
  =Parent-in-law=.
- =Other= (GLSS6 code 11, 14 people; distinct from code 10 =Non_relative=)
  folds into =Non-relative=: tuple [0,0,unrelated] either way.
- GLSS7's served =Non-Relative= (the country formatter title-cases the raw
  =Non-relative=) needs its own row: =.replace()= is exact, and a capital R
  is a different string.
- =Househelp (Other relative)= (GLSS7 code 9) and =House help (Non-relative)=
  (code 10) both carry [0,0,servant]; the annotation is not preserved.

=Others not related= (GLSS1's wording) is =Non-relative= as of 2026-09-07;
GLSS1/2's decode table (=relationship_glss1=) keeps the questionnaire wording
and this table harmonizes it, so the decode stays verbatim.

# harmonize_education (GH #171, #731): GhanaLSS attainment labels onto the
# canonical ordinal levels.  Ghana ran TWO school systems: OLD (Primary P1-6,
# Middle M1-4, Secondary S1-5/O-Level, Sixth Form/A-Level) and NEW post-1987
# (Primary, JSS/JHS, SSS/SHS).  Basic-cycle completions (M4/Middle, JSS3) ->
# Lower secondary complete; any senior-secondary completion (S5/O-Level,
# A-Level/Sixth Form, SSS3/SHS) -> Upper secondary complete.
#
# WHO READS THIS TABLE (2026-09-02, GH #731).  Only the three LETTER-LADDER
# waves resolve through it: 1987-88 and 1988-89 (Y03I.DAT:GRADE) and 1991-92
# (S2.DTA:s2q2), via `mappings: [harmonize_education, ...]` in their
# data_info.yml.  1998-99 maps its numeric s2aq2 codes inline in data_info.yml
# and never touches this table.  2005-06, 2012-13 and 2016-17 each carry their
# OWN `#+name: harmonize_education` in <wave>/_/categorical_mapping.org, which
# SHADOWS this table wholesale for that wave: Wave.categorical_mapping
# (country.py ~l.1006) is a plain dict.update over the country dict -- there is
# no row-union at the country/wave boundary (the row-union in
# _row_union_categorical, ~l.312, is global/country only).  A future wave must
# therefore add its OWN wave table rather than lean on this one.
#
# WHY (GH #731): the label `U6` means two different things in the two
# instruments.  GLSS1/2/3 ask "What was the highest class or form completed?"
# and print the ladder  NONE / P1-P6 / M1-M4 / S1-S5 / A1 A2 / PS1-PS3 /
# T1-T4 / U1-U8 / K (Koranic)  [+ JSS1-JSS3 in GLSS3] -- the sixth form is
# A1/A2 and U1..U8 are YEARS OF UNIVERSITY, so U6 is the sixth university year
# (GLSS1/GLSS2 household questionnaire, Section 3 block 3i printed p.6 col.7;
# GLSS3 G3QPartA.pdf p.10, Section 2A Q2).  GLSS5/6/7 ask "What was the highest
# grade completed?" and print  ... S5 / L6 / U6 / Voc-Tech / Teacher Training /
# Nursing / Polytechnic / University [GLSS7: Year one .. Year six and above]
# -- there U6 follows L6 and is UPPER SIXTH, a secondary rung (G5QPartA.pdf
# p.11 codes 32/33; GLSS6 Part A questionnaire p.10 codes 33/34; GLSS7 Module A
# codes 33/34).  This table used to list U6 TWICE (-> Upper secondary complete
# at the top of the modern block, -> Postgraduate in the U1..U8 ladder);
# _row_union_categorical's drop_duplicates(keep='first') silently kept the
# first, so the 13 GLSS1/2/3 people with U6 (1 / 4 / 8) were delivered as
# Upper secondary complete.  Now: U6 -> Postgraduate here, alongside U5/U7/U8;
# the modern waves' U6 -> Upper secondary complete lives in their wave tables.
# Measured 2026-09-02: slurm_logs/ghana_audit/u6_measure_731.out (raw labels
# per wave) and api_{before,after}_731.out (delivered counts).
#
# NOT settled here, deliberately: U1..U4 -> Bachelor.  The letter codes are
# YEARS COMPLETED, and the same instruments ask the qualification separately
# (GLSS3 Q3 "highest educational level attained": Bachelor=9, Master=10,
# Doctorate=11; GLSS2 col.10 "highest diploma obtained": BACHELOR=10,
# MASTER=11, DOCTORATE=12), so a completed U1..U3 is "some university" with no
# canonical rung of its own.  GhanaSPS reads its Level 100..300 as Tertiary
# certificate/diploma (PR #728).  Left as found; see CONTENTS.org Trap 7.
#
# ROW LAYOUT.  The rows the letter ladder needs are: NONE / None / none, B
# (GLSS1/2 never-attended skip code), K, P1-P6, M1-M4, S1-S5, A1, A2, PS1-PS3,
# T1-T4, U1-U8, JSS1-JSS3.  Every other row (lowercase GLSS5 labels,
# 'JSS3/JHS3', 'SSS3/SHS3', 'Year one..', 'L6', 'u6', 'Sixth Form', ...) is
# GLSS5/6/7 vocabulary that is INERT since 2026-09-02 -- shadowed by the wave
# tables and never emitted by GLSS1/2/3.  They are kept as documentation of the
# modern vocabulary only; pruning them is a follow-up, not done in GH #731.
