* New issue draft: Keep unreadable binary files out of the text-reader tail
get_dataframe's path-string retry calls pd.read_spss for unrelated formats;
ReadstatError is outside that attempt's caught tuple and can obscure the real
format diagnostic. Separately, an unreadable binary with a permissive encoding
such as latin-1 can reach read_csv and return an empty single-column frame whose
column name consists of binary header bytes. The null-read audit does not fire
on zero rows. The current DTA follow-up closes this for claimed .dta files only
(magic mismatch, or both Stata decoders failing), preserving the decoder cause.

Investigate format-aware binary-versus-text admission and explicit error chains
for other suffixes. Add failing-before tests for an unreadable non-DTA binary
under default and latin-1 encodings and for the SPSS path-string retry. Preserve
valid text, XPORT and legacy SPSS reads; do not blanket-catch programmer errors
or turn failures into empty data. Do not duplicate #712, which fixes CSV-to-Stata
misdispatch, or reopen #699's now-working XPORT path.
