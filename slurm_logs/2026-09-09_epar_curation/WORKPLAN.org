* How this is organised

Four phases, ordered by risk and by what unblocks what.  Phase 0 is
documentation and issue hygiene and can run today on this node; Phase 1
is low-risk additive code; Phase 2 is the substantive wiring and the one
corpus-wide change; Phase 3 is the schema proposal that unblocks GH #439;
Phase 4 is the numeric parity run and the upstream note to EPAR.  Each
item names the learning it acts on (=LEARNINGS.org= L1-L12, section 3
row numbers as N1-N12), what it touches, how to verify, and the
delegation model.  Effort is a rough estimate in agent-hours of
wall-clock, not a promise.

Delegation defaults (per @ligon, 2026-09-09): Sonnet or Haiku for search
and extraction, Opus for intermediate work and red-team, Fable in a pinch.
Every country-scoped agent reads =countries/{C}/_/CONTENTS.org= first and
names the idiosyncrasies it cross-referenced; every code change is
verified with =PYTHONPATH= set to the worktree and the
=assert 'worktrees' in lsms_library.__file__= guard.  Prior-art ledger
(=.coder/ledger/=) for every Phase 2 and 3 item.

Cache note: an edit to =transformations.py= moves
=build_transforms_fingerprint= only for =@build_transform=-tagged
callables; the parity transforms and =median_price_valuation= are
analyst-callable and outside the fingerprint.  =conversion_to_kgs= and
=_get_kg_factors= (Phase 2, L2/L3) ARE on the food build path and will
cold-rebuild every country's =food_quantities= / =food_prices=; plan a
corpus re-warm and a regrade after that item, not before.
