*CONCERN 1b -- two defects here, neither fatal today.*

1. The collision warning's own last sentence is *false*: "The frame keeps its own
   index shape."  It does not.  Case (e) shows the rename is skipped, and then the
   #498 extra-level drop removes =plot_id= anyway, so the country is silently
   re-shaped to canonical and its aliased level is discarded.  If the aliased
   level were the finer key, the follow-on =_collapse_duplicate_index= would eat
   rows -- audited, but the warning has pointed the reader the wrong way.
2. =_rename_index_levels='s clash test only inspects =df.index.names=.  A frame
   with the alias as a LEVEL and the canonical name as a COLUMN passes the test,
   gets renamed, and ends up with the same name in both namespaces.  If any
   sentinel level is also missing on that frame, =_align_to_canonical_levels='s
   =reset_index()= then raises =ValueError: cannot insert plot, already exists=,
   which =Feature.__call__='s broad =except Exception= converts into
   "Failed to load crop_production for X: ValueError: ..." and *drops the whole
   country*.  Loud, but the message names neither the alias nor the rename.

   *No country in the corpus is in this state today.*  Direct evidence: all 15
   stored =crop_production= frames were listed and *none* carries =plot=,
   =plot_id=, =crop= or =j= as a data COLUMN (only as index levels).  Corroborating
   inference: every country except Uganda is missing at least one sentinel level,
   so =reset_index()= runs on 14 of 15 frames -- a =plot=-column country would
   have crashed, and none did.  The one-line fix is to widen the clash test to
   =dst in names or dst in df.columns=.

*The sharper check -- can a sentinel-filled level collide?*  Two ways, and both
were tested:

1. Adding a CONSTANT level cannot create a duplicate (it refines nothing and
   distinguishes nothing).  Structural.
2. PROMOTING a column can, if a null and a literal sentinel value sit on rows
   that are otherwise identical.  Synthetic case 1j reproduces the collision.
   *On the real data it cannot happen*: 0 literal ='Unknown'= values in the =u=
   columns of Mali, Nigeria and Tanzania (item 2).  Empirically, the assembled
   14-country index is unique, and it stays unique with only Tanzania's 2,395
   promoted rows present.
   *CORRECTION to the docstring, and a real gap.*  =_align_to_canonical_levels='s
   docstring says promotion "can never make the index non-unique and can never
   reach =_collapse_duplicate_index=".  The first half is false for the promotion
   branch and the second half is true only because of the first: measured, the
   synthetic collision returns =index.is_unique == False= with NO collapse and NO
   grain report.  =_collapse_duplicate_index= is called from exactly one place in
   =feature.py= (line 540, inside the extra-level-drop branch), and
   =Feature.__call__= never checks =result.index.is_unique= after the concat.  So
   a genuine promotion collision would ship a silently non-unique =Feature= index
   -- the one failure mode with no guard behind it.
   =test_no_collapse_and_no_row_loss_on_a_duplicate_prone_frame= does not close
   this: it promotes =u=['Kg','Bag']= -- two NON-null, DISTINCT values -- which is
   the REFINING case, and asserts =out.index.is_unique=.  The null-collision case
   is untested.
   *The invariant therefore rests entirely on the data fact* (0 literal
   ='Unknown'= in Mali/Nigeria/Tanzania's =u= columns), not on structure.  Guard,
   three lines, in =_align_to_canonical_levels= after =set_index=:
   =if not out.index.is_unique: warn (or route through _collapse_duplicate_index)=.

** 7c. =plot_features= on =plot_id= vs =crop_production= on =plot= -- I upgrade this

Measured across the whole corpus:

: plot_features:   23 of 23 countries store the level as `plot_id`; registered `(t, v, i, plot_id)`
: crop_production: 11 of 15 store `plot`, 4 store `plot_id`; now canonicalised to `plot`
: plot_labor:      10 of 13 store `plot`, 3 store `plot_id`

*Is it a regression?*  No.  Base's =Feature('crop_production')= kept the modal
EHCVM shape, whose level is also =plot=, so a =plot=/=plot_id= join already
failed.  But the *scope* changed: base delivered 8 countries, none of which was
one of the =plot_id= countries; the branch delivers 14 including Ethiopia,
GhanaSPS and Tanzania -- countries whose own =crop_production= names the level
=plot_id=, matching their =plot_features=, and which now come back renamed to
=plot=.  For those three, a join that would have worked on the =Country()= frames
now needs a rename on the =Feature()= frames.

*Why I upgrade it from "follow-up" to a decision-now item*: =data_info.yml= now
*declares* two canonical indexes that name the same axis differently.  That is no
longer an accident of per-country config, it is a stated contract in the single
source of truth, and the next feature registered (=plot_labor=, =plot_inputs=)
will have to pick a side.  The mechanism this branch adds makes the fix a
one-liner in either direction -- either

: level_aliases: {crop_production: {plot: plot_id, crop: j}}   # canonical = plot_id, matching plot_features and all 23
: index_info:    crop_production: (t, v, i, plot_id, j, u, condition, season)

or the mirror change on =plot_features=.  =plot_id= is the cheaper side (23/23 of
=plot_features=, and it is already registered that way), at the cost of renaming
11 of 15 =crop_production= frames instead of 4.  This is a maintainer call, not a
bug -- but it should be made in this PR, not deferred, because the branch is what
makes the two declarations sit next to each other.

** #569 -- partial, and "one alias + one sentinel entry each" understates it

*=plot_labor= -- 1 alias, but 2 sentinels including a brand-new token, and the
cost of getting it wrong is 60,607 rows.*  Measured shapes over 13 warm countries:

: (t,i,plot,source)                        x10
: (t,i,plot_id,source)                     x2   (Ethiopia, Tanzania)
: (t,i,plot_id,season,stage,source)        x1   (GhanaSPS, 89,887 rows)

The entries would be:

: index_info:               plot_labor: (t, v, i, plot, season, stage, source)
: level_aliases:            plot_labor: {plot_id: plot}
: missing_level_sentinels:  plot_labor: {season: unknown_season, stage: unknown_stage}

measured, dropping =season= + =stage= collapses 89,887 GhanaSPS rows to *29,280
distinct index tuples -- 60,607 rows destroyed (67.4%)*.  Audited, but destroyed.

={last, major, minor}= -- *not the same as its own =crop_production.season=*
