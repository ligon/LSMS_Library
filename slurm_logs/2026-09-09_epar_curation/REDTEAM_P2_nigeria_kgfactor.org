* ITEM 5 — the cache trap :: *FAIL* (framework bug; the ledger's diagnosis is wrong)

** What the ledger claims

=.coder/ledger/859-nigeria-kgfactor.md= (and the =CONTENTS.org= §Cache entry by
implication) attributes the observed miss to the *=legacy= branch*:
=crop_production='s parquet is script-written and hashless, so the first read
graded =legacy= -> trust-once-and-stamp, and "one read, one edit — and the
window closes, which is why it is easy to hit once and impossible to reproduce
twice."

** What actually happens

That is not the mechanism, and the real one is *strictly worse*: it is not a
one-shot window, it fires on *every* hash move, and it never self-heals.

The chain, verified end to end:

1. =Country._table_cache_hash= moves (config edit).  The gate works: the read
   at =country.py:3804= grades =stale= and logs
   =v0.8.0 cache STALE: crop_production ...; rebuilding from source=.
2. The rebuild descends =load_from_waves= -> (no wave declares
   =crop_production=) -> =country_fallback = run_make_target('crop_production',
   wave=None)= (=country.py:3691=).
3. =run_make_target= tries =try_make= FIRST (=country.py:3538=), running
   =make -s <data_root>/Nigeria/var/crop_production.parquet= in
   =Nigeria/_=.  *Nigeria's =_/Makefile= has no rule for that target.*  GNU
   make, given a rule-less target that EXISTS as a file, reports it up to date
   and *exits 0*.  Measured directly:

   : $ make -s -n "<...>/Nigeria/var/crop_production.parquet"   # exists
   : exit=0
   : $ make -s -n "/tmp/nonexistent_xyz/crop_production.parquet"
   : make: *** No rule to make target ... Stop.
   : exit=2

4. =try_make= therefore logs =Makefile executed successfully ...=, finds the
   (stale) file in =unique_candidates=, and returns it.  *=try_script= — the
   only thing that would actually run =_/crop_production.py= — is never
   reached.*
5. The stale frame is read back and returned, then written at
   =country.py:3865= with =cache_hash=self._table_cache_hash(...)= — i.e. the
   *stale content is stamped with the NEW, correct hash*.  Every subsequent
   read grades =fresh=.  The bug has erased its own evidence.

** =_evict_hashless_wave_caches= (GH #479) does NOT cover this

=country.py:3219=: =country_root.glob(f"*/_/{method_name}.parquet")= with
=if p.parent.parent.name in ("_","var"): continue=.  That pattern matches
=<wave>/_/x.parquet= only.  The *country-level* =var/x.parquet= has no =_/=
component and never matches.  GH #479 closed the wave-level hole; the
country-level hole is untouched and, as far as I can find, undocumented —
=CLAUDE.md= §"Cache Behavior" override #1 describes the *soft* =LSMS_NO_CACHE=
case for *L2-wave* script parquets only.

** Why it slipped every guard

=_assert_built_required_columns= would have raised on a missing *required*
declared column.  =KgFactor= is =optional: true= (correctly — W1–W3 have no
source column), so the stale frame passed silently.  The =optional= flag that
is right for the data is also what removes the last tripwire.

** Already-filed neighbours — and why this is NOT one of them

=gh issue list= turns up two open issues on the country-level parquet:

- *#788* "A country script's output is laundered into looking framework-fresh:
  hashless =var/{table}.parquet= is trusted once and re-stamped" — and it
  already records that "=Country._evict_hashless_wave_caches= ... globs

  country-level counterpart for =var/{method_name}.parquet=."
- *#809* "Hashless country-level parquet written by a make recipe is trusted as
  legacy (#808 option 3)".

Both describe the =legacy= trust-once-and-re-stamp path — i.e. *the mechanism
the ledger names*.  *Neither covers the bug measured here.*  The distinction is
sharp and was tested: my reproduction stamped a *bogus* hash, so the parquet
graded *=stale=*, not =legacy=; the =legacy= branch was never entered; and the
bug fired anyway.  It is a defect of the *rebuild descent*, not of the read
gate.  Fixing #788/#809 (stamp make output, or refuse to trust a young hashless
file) would leave this untouched: a correctly-stamped-but-stale country parquet
would still be "rebuilt" by a =make= that does nothing and re-stamped fresh.

So: *file a new issue*, cross-referencing #788, #809, #803 and #479.
