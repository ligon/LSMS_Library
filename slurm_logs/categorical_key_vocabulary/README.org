* Headline numbers

| key type across 297 tables      | 141 label / 135 numeric / 21 mixed |
| tables with BOTH code and label | 30                                 |
| non-conventional positional key | 24                                 |
| ...of those, on a LIVE path     | *0*                                |

*The last two rows are the point.*  The positional key is correct everywhere it
currently fires, so =#+key:= is insurance for adding =Status=/=Notes= columns,
not a fix for a live defect.  The one live consequence of positional keying is
the silent merge fallback, which is why Malawi serves four spellings of the
kilogram over 146,284 rows while five sibling countries serve one.

* Ignorance spellings

The parser keeps the two authored forms distinguishable --- =---= becomes NaN, a
blank cell becomes the empty string --- so *NaN means somebody wrote the
sentinel and empty string means somebody left it blank*:

| =Unknown=            |  36 | =harmonize_education= x15, Niger =u= x4 (#842) |
| NaN (authored =---=) | 147 | *Uganda =u= 143*, EthiopiaRHS 2, Burkina 1, Malawi 1 |
| empty string         | 280 | GhanaLSS wave =harmonize_food= 264 (that is #925), Mali 5, EthiopiaRHS 4, GhanaSPS 4, Tanzania 3 |

* Two traps these scripts fell into

Recorded because both produced confident wrong answers first:

1. =Country.data_scheme= is a *list* of table names, not a dict.  Iterating it
   as =.items()= silently yields nothing.
2. In =data_scheme.yml= the tables are nested under a =Data Scheme:= key, and
   the file carries =!make= tags that =yaml.safe_load= refuses.  Reading the
   top level gives you table names where you wanted column names.

=reachability.py= asserts =Roof/Floor/Sex/Rural= are among the extracted
columns for exactly this reason: a silent miscount here changes the proposal's
conclusion.
