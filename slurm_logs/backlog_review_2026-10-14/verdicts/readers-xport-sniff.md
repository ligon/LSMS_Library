## 5. Residual risks and what a human must decide

1. **Stricter-than-pandas Stata gate** (bytes 1-2) -- the one path where this branch can turn a correct read into a silent wrong one. Zero of 4,811 held `.dta` are affected; 2,002 `.dta` sidecars have no local blob and were not sniffed. A `.dta` off-spec on byte 1 or 2 is no longer handed to the Stata readers; on my ONE synthetic file it then raised `ReadstatError` under both encodings, but the text tail is content-dependent (§1.7 shows `latin-1` makes `read_csv` succeed on arbitrary bytes), so for some byte patterns such a file read with `encoding='latin-1'` would be served as a silent garbage frame where development read the real table. Not blocking (nothing held is affected, and the spec-violating byte 3 was already excluded from the test on evidence), but the human choice is: accept the residual as stated, or make a suffix/magic disagreement LOUD -- a `.dta`-suffixed file that fails `_is_stata_dta` should warn or raise before reaching `read_csv`/`read_fwf`. The latter is consistent with sniff-not-widen and closes §5.2 for `.dta` at the same time.
2. **`encoding='latin-1'` + unreadable binary = silent `(0, 1)` frame** (pre-existing, both trees). Site R does not fire on 0 rows. This is the sibling defect the agent's new ReadstatError issue should absorb: the chain's tail (`read_csv` with a permissive encoding) is what launders, and a sniff-based gate on `read_csv`/`read_fwf` (reject NUL bytes in the head) would close it. Not this branch's regression; decide whether it goes in the drafted follow-up issue.
3. **Corpus-wide re-warm** is real and stated (37/37 class; measured on Peru both tables). The ruling batches it with #810/#868/#970; whoever merges must land those together or pay the re-warm twice.
4. `_SNIFF_BYTES = 64` vs its own comment ("48 covers the longest magic") -- harmless.
