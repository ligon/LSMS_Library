#+title: GH #741 -- verification against the built wheel
#+date: 2026-09-02

Not "the tests pass": the tests run against the repo tree, and #741 is about
what reaches a *pip user*.  The checks below run against the artifact itself.

* 1. The .enc actually ships
Built with the =poetry-core= backend directly (not the =poetry= CLI -- see
=slurm_logs/release_v0.10.0/burst_wheel.sh= for why):

: built: lsms_library-0.9.1.post208.dev0+fcec3642-py3-none-any.whl
: total entries: 11652
:   s3_reader_creds.enc  -> SHIPPED: lsms_library/countries/.dvc/s3_reader_creds.enc
:   s3_reader_creds.gpg  -> SHIPPED: lsms_library/countries/.dvc/s3_reader_creds.gpg

This is the check that matters most.  =.gitignore= has =**/.dvc/=, so the file
needs =git add -f=; and poetry ships nothing from that directory that is not
named in =[tool.poetry] include=.  Miss either and the fix works in the repo
and reaches nobody.

* 2. The issue's own repro, against the wheel's files, with no gpg
PATH rebuilt to hold =git= (GitPython needs it at import, as the issue's repro
has) but *not* =gpg=:

: git on PATH: True | gpg on PATH: None
: wheel creds files: ['s3_reader_creds.enc', 's3_reader_creds.gpg']
: UNLOCK SUCCEEDED: True
: creds INI-shaped : True
: warnings         : none

Before this change that path ended in =NoCredentialsError= from botocore.

* 3. The failure still degrades legibly
Same no-gpg PATH, with the =.enc= also removed from the extracted wheel:

It warns rather than raising on purpose: the NADA download path still works, so
this is a degraded mode, not a failure.

* What is NOT verified here
A real =pip install= into a clean venv on Windows or macOS.  Savio has no
outbound network for PyPI and no such host available.  What is verified is the
wheel's *contents* and the unlock running against those contents with the gpg
binary unreachable, which is the mechanism the issue describes.
