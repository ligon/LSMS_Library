# Ethiopia food compiler: household identity repair

The country compiler incorrectly applied the old `j`-as-household loop to canonical food, whose household axis is `i` and food axis is `j`. It now uses current `Country.updated_ids` and the shared per-native `id_walk(state='raw')`, with the framework's converted-frame guard. Existing declaration discovery, folder deduplication, squeeze, concat, food labels, quantities, expenditure, units, source channels and writer remain. The old one-column DataFrame writer shape is preserved explicitly.

The unchanged baseline compiler and framework reference each contain 326,456 rows, but differ on 75,367 observed household-key positions: W2 30,463 and W3 44,904. Quantity/Expenditure are exactly equal by original row position; this does not establish keyed baseline parity. The original failed comparison remains failed, including different attrs. An earlier blanket aggregate guard also incorrectly blocked the committed map-JSON route; that setup failure remains separate from the scientific comparison. A historical country-cache intake hash mismatch remains unadmitted, with no metadata/value cause inferred.
