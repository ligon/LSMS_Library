* 0. Scope, method, and what "absent" means here

READ-ONLY investigation.  Nothing under =lsms_library/= was edited.  The only
write is this file.

Method:
1. Enumerated every =*.dta.dvc= sidecar under
   =lsms_library/countries/GhanaSPS/{2009-10,2013-14,2017-18}/Data/= (124 + 89 +
   100 = 313 files).
2. Warmed each blob with =lsms_library.local_tools._ensure_dvc_pulled= (no =dvc=
   CLI was invoked at any point) and read Stata *metadata only* with
   =pyreadstat.read_dta(..., metadataonly=True)=, yielding 10,778
   (file, variable, variable-label) triples.  313/313 files read successfully;
   one (=2013-14/01fi_generaleducation.dta=) needed =encoding='latin1'=.  There
   are *no =unknown= cells in this report* -- every file was inspected.
3. Read actual values via =get_dataframe()= for every claim that turns on
   coverage or on a column being populated rather than merely declared.
4. Extracted full text of six instruments: wave-1
   =Household_questionnaire_Part_A.pdf= / =Part_B.pdf= /
   =Interviewers_Manual_household_survey.pdf= / the DDI report
   =ddi-documentation-english_microdata-2534.pdf=; wave-2
   =ISSER_Yale_Part A_WAVE II.docx= / =Part B_WAVE II.docx= / =Community
   Survey_WAVE II.docx=; wave-3 =HH_Questionnaire_23_10.docx=.

Verdict vocabulary used below, kept strictly separate per the repository rule
that *absence from the shipped =.dta= is not absence from the instrument*:

- =present(file)= :: a shipped data file carries the module.
- =absent-from-extract= :: no shipped =.dta= carries it; the instrument
  question is answered separately.
- =asked-not-distributed= :: the instrument asks it AND a document says the
  data exist elsewhere; quoted evidence given.
- =not-asked= :: the module does not appear in any household instrument I read;
  the search terms are listed so the claim is falsifiable.
- =unknown= :: could not fetch.  *No cell in this report is =unknown=.*

* 1. Idiosyncrasies found in =GhanaSPS/_/CONTENTS.org= (and =notes.org=, =README.org=)

Named, not merely acknowledged.

** I1. GSPS is a panel, not three cross-sections -- only wave 1 has a documented probability sample
CONTENTS.org: "GSPS is a *panel*, not three independent national
cross-sections.  Only wave 1 has a documented probability sample of Ghana.
Waves 2 and 3 are follow-ups of that sample plus households split off from it,
and *no document in the corpus states a universe for them*."  Wave-2 frame =
5009 wave-1 HH + 475 split-offs = 5484 selected, 4774 interviewed.
*Corroborated by the microdata*: 2017-18 =00_hh_info.dta= carries =remnant=
("Whether HH is a remnant (head split off)"), =FPrimary_original=,
=hhmid_original=, =last_wave= and =round=; 920 of 5,669 wave-3 households have
no =last_wave= (i.e. are new), and 682 distinct =FPrimary_original= values link
split-offs back to parent households.

** I2. Waves 2 and 3 are not in the World Bank catalog at all
Only wave 1 (WB study 2534) is; waves 2/3 exist only as IHSN/ISSER entries
10354 / 10355.  Consequence for this audit: the wave-2 and wave-3
=Documentation/= trees are thin (wave 3 ships exactly one document), so
questionnaire-grade (C4) evidence is unevenly available across waves.

** I3. The design is NOT self-weighting, and the oversample is regional
"Since the design is not self-weighting, household sample weights have been
computed and applied" (Basic_Information_Dec_2015.pdf, printed p. 9).  Upper
East (16 EAs) and Upper West (12 EAs) deliberately over-sampled vs. Ashanti
(60).  *Corroborated by the microdata*: =2009-10/key_hhld_info.dta= region
counts are Ashanti 900 households (= 60 EAs x 15), Upper East 240 (= 16 EAs),
Upper West 180 (= 12 EAs) -- exactly the documented Table 1 allocation.  So an
unweighted GhanaSPS mean is not a national mean, and =hhweight3= exists to fix
that (see F1).

** I4. The 6-month household-membership rule
"A person qualifies as a member of a household if he/she in the last 6 months
regularly participated in this living arrangement with the household."
CONTENTS.org cites this from the wave-1 Basic Information Document only.
*New corroboration from this audit*: the rule is restated verbatim in the
wave-3 instrument, =2017-18/Documentation/Questionnaire/HH_Questionnaire_23_10.docx=
(extracted text line 446).  So it is a standing survey definition, not a
wave-1-only statement.  This matters for roster-derived counts (see F2).

** I5. "'2013-14' has no regions or urban/rural data"
CONTENTS.org, under "Files in GhanaSPS/_/ > other_features.py", quoting the
data map: "'2013-14' has no regions or urban/rural data ... So 2009-10 (Wave 1)
has information but 2013-14 (Wave 2) does not.  For now, all of 2013-14 has
Ghana set as its region."  *CONFIRMED, with a sharpening* -- see the conflict
section 2 below.  The wave-2 extract does contain a file with geography
*columns* (=01ea_employmentscreener.dta=: =regioncode=, =regionname=, =eacode=,
=eaname=, =districtname=, =communitycode=) but *all six are blank in all 13,643
rows*.  Declared, never populated.  So CONTENTS.org is right and the
temptation to "just read the geo columns" is a trap.

** I6. Food-label harmonization is the whole point of the country's =_/= directory
=food_items.org= 's "Preferred Label" column and the West Africa Food
Conversion Table are the mechanism for comparing GhanaSPS to GhanaLSS.
=notes.org= additionally carries a hand-built =other_items.json= harmonization
for *non-food* expenditure labels across the three rounds (33 items,
"Preferred Label" column) -- machinery that already exists for a
=nonfood_expenditures= feature nobody has declared (see F13 and rank 7).

** I7. =notes.org= references parquets that no longer have producers
=notes.org= reads =../{wave}/_/food_expenditures.parquet=,
=other_expenditures.parquet= and =household_demographics.parquet=.  Only
=other_expenditures.py= survives in the wave =_/= dirs; the demographics
producer was deleted in commit =75143978= ("Remove 105 legacy other_features.py
and household_characteristics.py scripts").  The deleted scripts are the
cheapest available evidence of which source files a human already validated,
and I used them (=git show 75143978^:...=):
- 2009-10 roster: =../Data/S1D.dta=, HHID ==hhno=, age ==s1d_4i=, sex ==s1d_1=.
- 2013-14 and 2017-18 roster: =../Data/01b2_roster.dta=, HHID ==FPrimary=,
  age ==ageyears=, sex ==gender=.
- 2009-10 geography: =../Data/key_hhld_info.dta=, ==hhno=, ==id1= (region),
  ==urbrur=.
- 2017-18 geography: =../Data/00_hh_info.dta=, ==FPrimary=, ==region=.

** I8. =_/ghanasps.py= already encodes the wave-3 panel link
=Waves = {'2009-10':(), '2013-14':(), '2017-18':('00_hh_info.dta', 'FPrimary',
'FPrimary_original')}=.  The split-off remap is already wired for the
=food_acquired= path; a =panel_ids= feature would be re-using, not inventing.

* 2. CONFLICT: =data_scheme.yml= says cluster identity is unavailable.  It is available in two of three waves.

** The claim in force

(also repeated in =_/food_acquired.py= 's docstring):

** What the data show

*** 2009-10 -- the claim is FALSE on all three of its sub-clauses
- "no cluster var in the food files": =2009-10/S11A.dta= -- the very file
  =2009-10/_/food_acquired.py= reads -- carries =id3= with variable label
  "EA NO.", alongside =id1= "Region", =id2= "District", =id4= "HH ID".  So does
  every other wave-1 =.dta= except =S3AII/S3AIII= (which carry =id1=, =id2=,
  =hhno=).
- "EAs.dta is EA-level only": true of =EAs.dta= (2 columns, =id1= + =id3=), but
  irrelevant, because =key_hhld_info.dta= is the household-level cluster file:
  =hhno= + =id1= (Region) + =id2= (District) + =id3= (EA NO.) + =urbrur= +
  =loc7= + =hhweight3= + =ppweight3=, 5,009 rows, one per household.
- Verified: 334 distinct =id3= values (exactly the documented 334 EAs), 10
  regions, 335 distinct =(id1,id2,id3)= tuples -- i.e. one EA number is reused
  across two districts, so =v= must be the *composite*, not raw =id3=.
  =urbrur= = {Rural: 2999, Urban: 2010}; =hhweight3= populated for all 5,009
  (mean 1419.2).  Value labels decode cleanly ( ={1: Urban, 2: Rural}= ).

*** 2013-14 -- the claim is TRUE
No shipped wave-2 file carries a populated cluster, region, district or
urban/rural variable.  The only candidate,
=2013-14/01ea_employmentscreener.dta=, declares =regioncode=, =regionname=,
=eacode=, =eaname=, =districtname=, =communitycode= and populates *none* of
them (0 non-blank of 13,643 rows for each).  This matches I5 exactly.

*** 2017-18 -- the claim is FALSE, but coverage is partial
=2017-18/00_hh_info.dta= carries =r_code= (10 regions), =d_code= (199
districts), =comm_code= (704 distinct values) plus text =region= / =district=,
for all 5,669 households.  =rural-urban.dta= and =00_comm_info.dta= map
=(regioncode, districtcode, communitycode) -> communitytype=, value-labelled
={1: Urban, 2: Rural}=, over 528 communities (246 Urban / 282 Rural).
Measured: 828 of 5,669 households carry the missing sentinel
=comm_code = -666=, and a left join of =00_hh_info= onto =rural-urban.dta= on
=(r_code, d_code, comm_code)= matches *3,995 of 5,669* (70.5%).  Note the two
files are not identical despite having the same five columns
( =rural-urban.equals(comm_info)= is False ), which needs a look before either
is used as the authority.

** Consequence
The sentence "GhanaSPS has NO =sample= table (cluster identity unavailable)"
is, as written, wrong for 2 of 3 waves.  The *conclusion* (do not join =v= to
=food_acquired= today) is still defensible while no =sample= table exists --
but the stated reason is not the real one, and it is currently suppressing a
=sample= + =cluster_features= build that wave 1 fully supports and wave 3
supports for ~70% of households.  This is exactly the "unevidenced 'no module
here' claim in a YAML comment" the repository forbids.  *Recommend the comment
be corrected in whichever PR next touches this file* (out of scope here --
read-only).

* 6. Reproduction

The metadata sweep, the searchable variable index, and the extracted
questionnaire text were written to this session's scratchpad, not to the repo.
To regenerate: iterate the =*.dta.dvc= sidecars under
=GhanaSPS/{wave}/Data/=, call
=lsms_library.local_tools._ensure_dvc_pulled(path)=, resolve the blob to
=_DVC_CACHE_DIR/md5[:2]/md5[2:]=, and read it with
=pyreadstat.read_dta(blob, metadataonly=True)=; dump
=(file, column_name, column_label)= triples.  Questionnaire text:
=pdfminer.high_level.extract_text= for the wave-1 PDFs,
=unzip -p f.docx word/document.xml | sed -e 's/<[^>]*>//g'= for the .docx.
