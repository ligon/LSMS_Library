** Answer
- *Superseded for everything currently wired.*  Six of the nine YAML-wired
  files are pre-anonymization copies; every variable the YAML names in all
  six is present in the public copy's DDI.  Replacing those six with the
  Dataverse files would change no wired column.  (Whether values match
  row-for-row is not tested here -- the findings doc verified identical row
  counts on 2026-08-19; a value-level diff needs a venv and the blobs.)
- *Not superseded for one thing nobody reads yet:* the sub-district
  geography stripped from =00_hh_info= (=d_code=, =district=, =comm_code= per
  GH #140; three variables gone, attribution not re-verified) is what a
  =sample= / =cluster_features= feature would be built on (GH #579).  That is
  the one reason to keep any pre-anonymization file, and if kept it is the
  first =gpg-recipients= customer that is *already in the bucket*
  (=SkunkWorks/holder_gated_access.org=).
- *Correction to the findings doc:* =01fi_employmentmain.dta= is listed
  there as "only in ours" (vs IHSN).  Dataverse v1.2 Wave 3 has it
  (1,150,873 bytes, 65 variables); ours is a 1,273,246-byte
  pre-anonymization copy.  The four with no public counterpart are
  =00_comm_info=, =01c_consentunder18=, =public_services=, =rural-urban=;
  none is wired (the YAML says =rural-urban= is the only urban/rural source
  and is NOT wired).

* What this does and does not settle
It settles that option B/C of =FINDINGS_ghanasps_provenance.org:706-708=
(replace the differing files with the public release; add the 11 missing)
costs nothing at the API today.  It does not settle the terms of the 100
files, which =LICENSE.org= still asks to be resolved, and it does not decide
#579's geography question.
