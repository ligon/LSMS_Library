#+TITLE: Evidence for the null-content read guard (lsms_library/null_read_audit.py)
#+DATE: 2026-08-22

The threshold in =null_read_audit._NULL_FRACTION_TRIGGER= is not a guess.  This
directory is the measurement it was chosen from, kept so the choice can be
re-checked rather than trusted.  Design rationale lives in =CLAUDE.md= §"The
Silent All-Null Read" and =.coder/ledger/null-read-guard.md= §7.

* Environment

Cold.  =LSMS_DATA_DIR= pointed at a private, initially-empty directory whose
=dvc-cache= was symlinked to the shared L1 blob cache.  L1 holds immutable
content-addressed copies of the raw =.dta= -- sharing them changes nothing
measurable.  The *parquet* tiers (L2-wave, L2-country), which are what could
have faked a clean result by short-circuiting =get_dataframe= entirely, were
private and cold.  Python =.venv/bin/python= (pandas 3.0.2),
=PYTHONPATH= asserted onto the worktree.

* Site R -- every declared source read once through =get_dataframe=

- =enumerate_reads.py= :: walks every wave's =data_info.yml= (=file:= plus every
  =dfs:= sub-block) via the real =Wave.column_mapping=, plus
  =local_tools.scan_script_data_refs= over every wave/country =_/ *.py=.
  2,264 distinct (country, wave, file) references, 0 enumeration errors.
- =sweep_reads.py= :: reads each one with =get_dataframe= at its own defaults
  and records shape, the all-null column list, and the state of every raw column
  a table actually asks for.  Refs neither on disk nor DVC-tracked are recorded
  =not-held= -- *never* as clean.
- =read_sweep.jsonl.gz= :: the 2,264 records.
- =analyze_reads.py= :: the summary below.

| test                                          | firings                      |
|-----------------------------------------------+------------------------------|
| any column 100% null                          | 887 cells / 153 files        |
| ...that a table actually ASKED for            | 3                            |
| frame with >= 1/3 of columns all-null         | 0  (corpus max 0.283)        |
| frame 100% null                               | 0                            |

Denominators: 1,337 files read (65,099 columns); 909 not-held (772 are
=.parquet= build *outputs*, not sources); 18 unmeasured (the read raised).

Threshold sensitivity (files firing, of 1,337): >=0.20 -> 2; >=0.25 -> 2;
>=0.30 -> 0; >=1/3 -> 0.  The only frames above 0.15 are Albania 2004
=w3_hh_basic.dta= (169/598 = 0.283), Niger 2018-19 =s20_me_ner2018.dta= (0.182),
Burkina Faso 2021-22 =s00_me_bfa2021.dta= (0.176) and Serbia and Montenegro 2003
=non-food consumption.dta= (0.155).

** The known-bad parses, on the real blobs

Reproduced directly, because the threshold is only defensible if the gap between
healthy and broken is real:

| file                              | reader                    | all-null cols |
|-----------------------------------+---------------------------+---------------|
| Peru =EXPEND.SSP=                 | =pyreadstat.read_xport=   | 2 / 5  (0.40) |
| Peru =PANEL.SSP=                  | =pyreadstat.read_xport=   | 2 / 4  (0.50) |
| Peru =N00A.SSP=                   | =pyreadstat.read_xport=   | 7 / 10 (0.70) |
| GhanaLSS =COMM.DAT= per =COMM.DCT=| =pd.read_fwf=             | 254/311(0.82) |

All four read cleanly with the right reader (=pandas.read_sas= / =pd.read_csv=):
0 all-null columns.  Corpus max 0.283 vs known-bad min 0.40 -- =1/3= sits in the
gap.

*Both classes are PROSPECTIVE.*  =Country('Peru').data_scheme == []= and no
declared table reads =COMM.DAT= (0 matches in the manifest), so neither can fire
on today's corpus.  Site R protects the parse work now in flight (GH #699 and
the =.DAT=/=.DCT= reader), it does not clean up after it.

* Site B -- every declared table built cold

- =sweep_build.py= / =build_sweep.jsonl.gz= / =analyze_build.py=.
- 504 builds, 488 completed.  The 16 that did not: Nepal (11) and Armenia (2)
  hold no microdata; Ethiopia =food_coping=, Panama =food_acquired= and Togo
  =people_last7days= are parallel-=make= contention -- all three build clean on
  retry with *zero* findings, so they add nothing to the count.

| test                                                    | firings              |
|---------------------------------------------------------+----------------------|
| REQUIRED declared column 100% null in EVERY wave        | 0                    |
| REQUIRED declared column 100% null in SOME wave's =t=   | 86, over 42 of 488 tables |

Spread over 17 countries; worst are Niger, Uganda and Malawi at 5 tables each.
Note =GhanaLSS/sample/weight= and =panel_weight= empty in four of six waves --
that country has been served with no sampling weights at all.

* Cache-hash probe

=hash_probe.py= computes =Country._table_cache_hash= for 37 (country, table)
cells across six countries covering both build routes, plus
=build_transforms_fingerprint=.

| state                                            | file                     | moved |
|--------------------------------------------------+--------------------------+-------|
| baseline (development)                           | =hash_before.json=       | --    |
| a bare no-op stub call added to =get_dataframe=  | =hash_after_stub.json=   | 37/37 |

Reading: Site B is free -- =Country._finalize_result= is already in
=_build_registry._EXCLUDED_CALLABLES= as read-path code.  Site R costs a
one-time corpus-wide invalidation, and the stub row proves that is *not* about
this guard: **any** edit to =get_dataframe='s body does it, because the tagged
=df_data_grabber= references it.  The concurrent =.DAT=/=.DCT= parse fix edits
the same function and pays the identical bill.

* Overhead

- Site R, largest read in the corpus (Malawi 2016-17 =hh_mod_g1.dta=,
  1,755,027 x 28): 0.49 s on a 14--18 s read, ~3%.
- Site B, largest built table (GhanaLSS =food_acquired=, 5,259,344 x 3):
  196 ms on a 167 s warm read, 0.1%.  (=bench_siteb.py=.)

* What this did NOT measure

- 137 script-route source refs whose relative path the sweep's resolver could not
  reconstruct (Nigeria's =Nigeria/2010-11/Data/*.csv= literals are
  countries-root-relative, not =_/=-relative; some are f-string fragments that
  =scan_script_data_refs= cannot see at all).  Recorded =not-held=, i.e.
  *unmeasured*, never clean.
- Nepal, Armenia (no microdata) and Peru (unreadable today) contribute nothing.
- Warm-cache divergence: everything here is cold by construction.
