* Placement: ABOVE =#+name:=, never below (a result that contradicts the issue text)

The issue (and =slurm_logs/2026-09-18_categorical_composition/DESIGN.org=)
put =#+key:= between =#+name:= and the table, verified only against the
library's own parser.  In Org itself that placement breaks the table's name:
=#+key:= is not an Org affiliated keyword, so =#+name:= attaches to the
keyword line and the table is left unnamed.  Measured with Emacs 29.1
(=emacs --batch -Q=, =org-element-parse-buffer= + =org-babel-ref-resolve=):

| placement                      | org-element sees                  | =org-babel-ref-resolve "u"= |
|--------------------------------+-----------------------------------+-----------------------------|
| =#+name: u= / =#+key: Code= / table | keyword name="u"; table name=nil | (error "Reference not found") |
| =#+key: Code= / =#+name: u= / table | keyword name=nil; table name="u" | the table                   |
| =#+name: w= / =#+attr_lsms: :key Code= / table | table name="w", attr_lsms (":key Code") | the table |

So the parser accepts =#+key:= only in the run of =#+= lines directly above
=#+name:= and refuses it below, with the reason.  The DESIGN.org composition
keywords (=#+keyspace:=, =#+fold:=, =#+column:=) are shown below =#+name:= too
and inherit the same hazard.
