* Behavior and boundaries
=provenance.py:221,245,410,490= share primary-URL selection between parsing and preserved prose.
Only explicit =CATALOG_URL= or the body preceding metadata supplies the primary URL.
Secondary metadata and note URLs cannot route acquisition.
Unknown keys retain every value, including repeated and empty occurrences; keyword-looking note lines and paragraph breaks survive.
Only one occurrence of the chosen bare primary URL is boilerplate; additional bare URLs, even a repeated primary URL, remain notes.
The no-URL placeholder is idempotent and is removed from notes where an older writer re-ingested it.

Known scalar accessors keep their historical last-nonempty value.
The appended =scalar_keywords= field retains repeated known scalar occurrences and explicit empty values for direct parse/render.
Changing a scalar without reconciling its retained occurrences raises an explicit ValueError before SOURCE bytes are written.
A backfill reconstruction that loses such occurrences is refused by its occurrence-count guard.
This deliberately does not promise arbitrary byte-for-byte Org preservation: keyword groups render in canonical order, whitespace is normalized, list-valued =CATALOG_ID=/=CATALOG_COVERS= retain membership rather than duplicate spellings, and a legacy record may receive canonical metadata.
An explicit empty URL/source whose accessor must infer a nonempty value cannot be rewritten automatically while retaining both meanings; it is refused rather than silently losing the empty fact.

=backfill_wave_provenance.py:617,652,885= protect held IDNO/DOI, maintain latest IDNO/DOI/first-seen separately, and report missing held releases.
Repeated observations preserve first-seen; temporarily absent catalog DOI does not erase a queued DOI.
An existing observation survives a missing held IDNO without being promoted to a held fact.
A stamped primary-entry correction with held IDNO or DOI is refused, rather than assigning the new entry's release from catalog metadata.
Legacy routing corrections without a held release remain supported and receive no held IDNO.

=data_access.py:1002,1562,1652,2156,2444= reuse the parser URL rule and existing actual extraction receipts.
A requested push must confirm every expected path, not merely return the right list length; failed, partial, duplicate and exception outcomes retain SOURCE and its latest queue.

An existing SOURCE record stays byte-identical during a failed cross-entry download; a private acquisition-only URL override selects the requested entry without overwriting held/unknown facts first.
The override requires both =populate_cache=True= and the existing acquisition opt-in context.
Ordinary reads keep the default path and cannot use this override.
