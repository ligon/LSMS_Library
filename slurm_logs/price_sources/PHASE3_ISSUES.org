* Needs coordinator (core redesign, not a fix)

None of the filed issues requires a core redesign to *land*, but two carry a
design decision inside them and are flagged in their bodies rather than as
separate drafts:

- *#840 (P03, variety collapse)* -- both candidate fixes are policy.  Adding
  =variety= to the index is a schema change that fans out every consumer joining
  on =(t, v, j, u)=; selecting on a stated rule is a reducer, which Tanzania's own
  code comment rejects citing GH #323 D1 ("fix the index; do not declare a
  reducer").  A maintainer must choose; GhanaLSS's =obs= level is a third shape.
- *#839 (P16)* carries a framework smell worth its own decision: a *comment* appended
  to =Mali/_/data_scheme.yml= moves all five probed Mali table cache hashes, while
  the same edit to =CONTENTS.org= moves none, because =Country._table_cache_hash=
  hashes the file bytes by name.  There is therefore no way to correct a false
  comment without paying a corpus rebuild -- a standing incentive to leave false
  claims in place.  Hashing the parsed YAML would remove it.

* Evidence discrepancies found while checking

*Two.*  The first is a contradiction and forced an edit to an issue I had already
filed; the second is a paraphrase.

** 1. Niger's NULL =u= rows are SERVED, not deleted (#842 corrected)

=Niger/REPORT.org= D7 says the 441 =crop_production= and 12 =food_acquired= rows
with a NULL =u= are "deleted outright by the framework's NaN-key =groupby=
collapse".  *The row's own evidence refutes its symptom*: the count comes from
=getattr(c,n)().reset_index().u.isna().sum()=, a probe of the *delivered* API
table, which would return 0 if the collapse had removed them.  Re-verified against
the live API on the warm cache:

#+begin_src
crop_production rows 41896 u isna 441
food_acquired   rows 239031 u isna 12
#+end_src

So the rows are served with a NaN on a declared index level, and the deletion is a
*downstream hazard* -- pandas' =dropna=True= default in any consumer =groupby=,
=Feature()= assembly, or =_normalize_dataframe_index= if the index ever goes
non-unique -- not something that has already happened.  #842 was filed with the
report's wording, then corrected in place (title and body, with the correction
recorded in the issue itself).  The counts are unchanged.

** 2. A paraphrased docstring in Uganda D5

=Uganda/REPORT.org= D5 quotes =transformations.py:1368-1372= as documenting =unitprice= as "the survey's
own price question".  The literal docstring says: /"reported =Price= (currency /
native u).  NaN where the survey did not record a unit price.  This mode reflects
the canonical =food_acquired.Price= column -- market price for =s='purchased'=,
farmgate for =s='produced'=, imputed for =s='inkind'="/.  The paraphrase is fair
and the substance stands, but #845 quotes the literal text and says so.
