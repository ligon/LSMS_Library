* Scope and method

Read-only census of every place a SERVED number (or index value) in these
eight countries is computed from raw fields rather than copied from one.
Inputs: every wave script (~135 =_/{table}.py=), every =data_info.yml= (34),
every wave =mapping.py=, the eight country modules, =data_scheme.yml= and the
country Makefiles, plus the shared transform they invoke
(=build_transforms.food_acquired_to_canonical=, imported through
=transformations=).  Everything was read as text with =grep= / =sed=; nothing
was executed, no =Country()= / =Feature()= call, no =dvc=.  The GitNexus MCP
server did not connect (CONNECTION_CLOSED), so call-site sweeps used =rg= /
=grep= per the CLAUDE.md substitution table.

Paths below are relative to =lsms_library/countries/= unless they start with
=lsms_library/= or =slurm_logs/=.  Excluded per the brief (renames, label
decoding, canonical spellings, dtype coercion, id construction, reshapes,
concatenation, lossless de-dup, non-food drops, v joins) are listed in the
appendix only where they were easy to mistake for a derivation.  The four
framework-derived tables (=food_expenditures= / =food_prices= /
=food_quantities= / =household_characteristics=) belong to the framework
census; only country-local versions of them are recorded here.

Kind vocabulary is the brief's nine plus one this group needed: =sum= (a
sum or difference across DIFFERENT raw fields, including counts of Yes over
several items).  Where one served value is produced by more than one rule
the =kind= cell lists them =primary+secondary=; the counts in section 3 are
by primary kind.  An =id= column is prepended to the brief's ten columns so
the notes can cite rows.

* 2. Per-derivation notes

Each note: what is baked in, and whether the raw inputs can be recovered
from the served table.

** GhanaLSS

- G1 (the motivating case).  =VFOODCPD= answers "how much would it cost to
  buy the amount they ate each time" -- a value per EATING OCCASION.  The
  script writes it into the same =Expenditure= column that, for
  =s='purchased'=, holds =CFOODBLV= "spent since my last visit" (~14 days),
  and (via G2) into =Quantity= with =u='Value'=.  The frequency
  (=TFOODC= with time-unit code =UTFOODC= 3..8, FINDINGS l.132-133) and
  months (=MFOODCLY=) that would
  turn it into a recall value are read for nothing.  The docstring's "per
  day" gloss entered in c404b7fb2 with no source and is wrong.  Verified
  against GSS's own =EXPEND.HPFOOD= in
  =slurm_logs/2026-09-11_ghanalss_visit_dates/FINDINGS.org= sect. 2.2:
  =VFOODCPD x TFOODC x (30.4/days_per_unit) x MFOODCLY= reproduces
  =HPFOOD= (median ratio 1.020); the served value is 1.3-1.7% of it.
  Served own-production share is 17-18% against 33-52% like-for-like.
  =CONTENTS.org= l.1256 lists 12B as "single recall", which is the
  opposite of what the file holds.  NOT recoverable: none of TFOODC,
  UTFOODC, MFOODCLY reaches the served table.  Taxonomy: nothing in the
  brief's nine kinds names "a raw value of a different meaning served
  under a column's name"; =encoding= is the nearest and understates it.
- G2.  =Quantity := Expenditure= with =u='Value'= is a deliberate
  convention (price 1.0 by construction) and is the best-disclosed rule in
  the group.  Recoverable trivially (the two columns are equal).  Its cost
  is downstream: G15 must drop every such row, and the kg inference
  (=CONTENTS= l.1905) has no purchase quantities for about two-thirds of
  GhanaLSS food_acquired (3,492,915 of ~5.26M rows).
- G3 / G4.  Weight 1.0 is asserted from the self-weighting design; the
  mirror =panel_weight := weight= is a convention repeated in six of eight
  countries (G4, M19, A7, B15, S12, GS15, C13).  Recoverable (constant /
  duplicate).
- G5.  =+1900= is safe for these waves; recoverable.
- G6, G9, G10, G11.  Four waves resolve the produced-side =Price= four
  different ways: broadcast a single farmgate price across 10 visits
  (1991-92), =first()= of duplicates (1998-99), quantity-weighted mean with
  a first-price fallback when =sum(Q)==0= (2005-06), unweighted mean then
  broadcast (2012-13).  None is recoverable from the served table (the
  duplicates are gone); 2005-06's per-row choice between the two rules
  depends on data, so a per-row label would have to name which branch
  fired.
- G7, G8, G19.  Sentinel and zero guards.  G8 ("0 is missing") is disclosed
  only by a comment and silently turns "bought nothing" into "not asked".
- G12.  FIES: a NaN item counts as 0 unless all eight are NaN; the served
  score cannot tell 3-of-8 from 3-of-5-answered.
- G13 / G14.  =NumberOfUnits= is the product of a raw count and a lot-size
  constant from a hand-maintained table, or (1991-92, 1998-99) the constant
  alone; the raw =QUANn= is recoverable only where Basis == 1.
- G15.  The x10 per-100g -> per-kg factor and the kg quantities from the
  framework inference compound; the served nutrient carries neither.

  no year column (2009 =HH4_Y= blank); 1999 adds 1900.  Any fieldwork that
  crossed a calendar year is mis-dated.
- T3.  =AreaUnit := 'sotka'= is a constant and =Area= is NOT converted, so
  the same column that holds hectares in Albania, EHCVM and GhanaSPS holds
  1/100 ha here.  A =Feature('plot_features')= consumer reading =Area=
  across countries is off by 100x for Tajikistan unless it reads
  =AreaUnit=.

** The cases where the served number is furthest in meaning from the raw answer

1. G1 GhanaLSS 1987-88 / 1988-89: a value per eating occasion served as
   a ~14-day recall value beside genuine recall values.  Served figure
   is 1.3-1.7% of the GSS reconstruction; own-production share 17-18%
   vs 33-52%.  The docstring says "per day", CONTENTS says "single
   recall", both wrong; the only correct account is a slurm_logs
   FINDINGS file dated today.
2. G2 GhanaLSS six waves: =Quantity := Expenditure= with =u='Value'=.

   them (G15 does; a naive =Feature('food_acquired')= consumer does not).
3. B2 Burkina 2014 =MonthsSpent=: a duration bin mapped as a membership

4. GS5 GhanaSPS 2009-10 =MonthsAway NaN -> 0= (47.3% of persons) and GS8b

** What would not fit a per-row Derivation column keyed to a registry

- Derivations of an INDEX VALUE rather than a column: B1a =visit= from a
  filename, B1b/GS10/B12/S9/C9 =u= / crop fills, G2 =u='Value'=, GS7/GS12
  =season= constants.  A row's Derivation cell has no index-level slot.
- Raw inputs that are not fields: B1a (the file), GS7 2009-10 (the file),
  GS4 (factors learned from another wave's data), A3 (another wave's
  table), T2 (a hardcoded year).
- Values borrowed across grain: M15 (HH purchase on plot rows), GS8b
  (plot-dominant crop on every crop), GS12 (plot rate on 7 stage rows),
  G6/G11 (one price on 10 visits).  The registry entry is the same on
  every stamped row, but the fact that N rows share ONE raw observation
  is what matters and is not per-row.
- Per-row branch selection inside one rule: M17/B8/S6/C6a (GPS vs
  estimate, and whether the clamp fired), G10 (weighted mean vs first
  price), GS6 (grade vs qual vs attended), age_handler (DOB vs reported),
  B6/S7/C8, GS9 (units agree or not), G2 in 2016-17 (conditional).  A
  registry name identifies the rule; the row still needs the branch.
- Nested derivations: T1b category over nine derived items; G15
  nutrients over framework-inferred kg; B14b median-of-derived-price.
- Sums whose NaN policy is not recoverable: FIES / HFIAS / B4 (NaN item
  counts 0 -- the served score does not say how many items were answered).
- Two taxonomy gaps: no kind for a sum/difference across different
  fields (used =sum= here, 20+ rows), and none for G1's "different
  question served under this column's name" (recall-window / meaning
  substitution), which is the case the design is motivated by.
- Live but conditional code: B14a/B14b serve only when the primary path
  fails; a static per-row column cannot express "derived by X unless Y
  failed, then by Z".
