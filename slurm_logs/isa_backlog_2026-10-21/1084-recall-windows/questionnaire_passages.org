Short quotes and page numbers only; no PDF, no extracted full text, no row-level
data.  Every file below is a held Documentation file, fetched with
=lsms_library.data_access.get_data_file= and extracted with pypdf (scratch
=PYTHONPATH= only) or, for the EHCVM .xls forms, xlrd.  "PDF p." is the
physical page; "printed" is the number on the page where it was checked.

The "build check" lines read Stata variable LABELS (metadata only,
=pyreadstat.read_dta(metadataonly=True)=) of exactly the columns the wave's
build reads, plus two structural counts that are not row-level data: the
number of rows per (household, item), and the range of the days-consumed
column.  The CSV rows (=.coder/coverage/food_recall.csv=) carry the same
citations.

*2018-19 numbering mismatch (content matches):* the printed form numbers the
purchase-at-home qty/value CEB04/CEB05 ... in-kind CEB10/CEB11; the shipped
=GSEC15B.dta= calls the same columns CEB06/CEB07 ... CEB012/CEB013 and splits
the market price into CEB14a/b/c.  The wave script reads the .dta names, whose
labels carry the same 7-day questions; the window is unaffected.

*The =[RECALL]= fill.*  2010-11..2015-16 food labels carry the un-substituted
=[RECALL]= / =[PERIOD]= placeholders, the template Uganda/_/CONTENTS.org
discusses for the NON-food GSEC15C.  For food, every printed form fixes the
window at 7 days, and the days-consumed column never exceeds 7 in any of the
five waves -- an item-specific window longer than 7 days would push daily
staples past 7.
