* The defect

PR #1221 (=326b6e3de=, GH #1218) made =country._empty_declared_frame= apply declared dtypes.
That helper is reached from the tagged =Country._aggregate_wave_data=, so its closure is in every table's =build_transforms_fingerprint=.
Through it, eight READ-path symbols entered every closure (measured by closure-part name, =326b6e3de= against =60aa81e9e=):
=_enforce_declared_dtypes=, =_coerce_datetime_column=, =_to_datetime_mixed=, =_coerce_to_boolean=, =_SCHEME_DTYPE_MAP=, =_SCHEME_SKIP_KEYS=, =_STR_TO_BOOL=, =_YEAR_LAST_DATE= (all =lsms_library.country.=).
=_SCHEME_DTYPE_MAP= holds =pd.StringDtype()=, whose storage is fixed at import by =mode.string_storage=, so every hash depended on that pandas option.

The frame is returned before any write on both callers; the probe below confirms no =<table>.parquet= appears in the data root on either backend.

* The change

1. ="lsms_library.country._empty_declared_frame"= is in =_build_registry._EXCLUDED_CALLABLES=, beside =_finalize_result= and the read gates.
   After it, the closure is exactly =60aa81e9e='s 186 names minus =_empty_declared_frame= (185); none of the eight remains.
   Other routes: =_enforce_declared_dtypes= is also called at =country.py:4008=, inside the already-excluded =_finalize_result=; no =countries/**/*.py= imports any of the eight, so =framework_imports_fingerprint= cannot reach them.
   (=lsms_library.datetime_parse._YEAR_LAST_DATE= is still in the closure, through the tagged parser, scoped to =interview_date=, as on =60aa=.)
2. Empty calendar payload columns are built as =datetime64[us]=, the GH #1045 stored resolution.
   =datetime_parse= has no named constant; it spells the unit as the literal ="datetime64[us]"=, and the helper uses the same literal.
   Previously they came out =datetime64[s]= (pandas' inference on an empty object Series).
